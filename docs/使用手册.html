一、系统概览#

本系统用来管理公司的 IT 资产：设备台账、组织归属、领用交接、保修跟踪、批量导入导出，并支持在手机上拍照识别设备品牌与 SN 号快速入库。

三个访问入口#

入口地址用途
管理端（电脑）http://<服务器IP>:8080/全部管理功能，建议用 Chrome / Edge
移动端（手机）https://<服务器IP>:8443/m现场拍照识别、扫码核对。必须是 https，否则相机用不了
公网访问https://itam.<你的域名>:<端口>/出差在外也能用，需由管理员部署

💡 手机首次打开自签证书的地址会提示「不是私密连接」，点 高级 → 继续访问 即可。

浏览器要求#

  • 电脑：Chrome / Edge / 火狐 等现代浏览器（不支持 IE）
  • 手机：系统自带浏览器、Chrome、Safari 均可；相机功能要求 https

三、账号与权限#

3.1 查看和修改自己的账号#

点右上角 账号：

  • 可以看到自己的用户名、姓名、角色、权限数量
  • 可以改姓名和密码（改密码需要输入当前密码）
  • 点「我的登录记录」可以看到自己最近的登录时间、IP、设备

⚠️ 修改密码后，你在其它设备上的登录会全部失效，需要用新密码重新登录——这是正常的安全机制。

3.2 四种角色能做什么#

角色适合谁能做什么
系统管理员IT 负责人全部功能：设备增删改、组织分类、Excel 导入导出、回收站、用户管理、系统设置
资产管理员资产专员设备增删改、组织分类、Excel 导入导出、回收站、查看审计日志；不能管用户、不能改系统设置
录入员现场录入人员查看设备 + 新增/编辑设备（含手机拍照录入）、导出 Excel；不能删除设备
只读领导 / 其他部门只能查看仪表盘、台账、组织、分类，不能做任何修改

权限是服务端强制校验的：即使绕过界面直接调接口，也会被拒绝（返回 403）。

3.3 忘记密码怎么办#

  • 找系统管理员，在「用户管理」里点「重置密码」，会生成一个一次性随机密码给你
  • 用这个密码登录后，系统会提示你立即改成自己的密码
  • 如果管理员自己忘了密码，需要在服务器上运行：node server/reset-password.js

五、手机端：拍照识别入库#

这是本系统最省事的功能：对着设备铭牌拍一张照，自动识别出品牌、型号、SN，核对后一键入库。

5.1 手机上怎么打开#

  1. 手机连接与服务器同一个 WiFi
  2. 浏览器打开 https://<服务器IP>:8443/m
  3. 首次会提示「不是私密连接」→ 点 高级 → 继续访问
  4. 浏览器询问是否允许使用摄像头 → 点 允许
  5. 顶部可以填「录入人」姓名（会记进操作日志，且会被记住）

如果一直提示打不开相机，多半是用了 http:// 而不是 https://——相机必须在 HTTPS 下才能调用。

两端可以互相跳转#

从哪 → 到哪入口
电脑端 → 手机端左侧菜单最下方「📱 打开移动端录入」
手机端 → 电脑端⭐ 两种：① 顶栏右上角的显示器小图标；② 首页最下方「回到电脑端管理后台」
两端 → 使用手册电脑端左侧菜单「使用手册」；手机端首页最下方「使用手册」

手机上只能拍照录入、扫码核对、查最近设备。改数据、看报表、导 Excel、管账号都要回电脑端——所以手机端特意放了两个回去的入口，不用再手敲网址。

5.2 拍照识别入库（完整流程）#

  1. 点 📷 拍照识别入库
  2. 把设备铭牌上的 SN 条码或文字放在取景框内，点白色快门按钮
  3. 出现照片预览，点 🔍 识别

> 📸 按下快门的那一刻，系统已经自动准备了 3 份照片（原图 / 识别图 / 缩略图）， > 识别成功后自动归档到这台设备名下，不需要你点任何保存按钮。

  1. 系统自动识别并填入：
字段说明
品牌显示置信度。若显示「由 SN 前缀推断」说明是根据序列号猜的，请核对
型号同上
SN 序列号关键字段，置信度最高，仍建议眼神核对一遍
  1. ⭐ 照片就在上面，对着比一遍：识别结果最上方是刚拍的那张铭牌照片缩略图，

照片在下、字段在上，一眼就能看出 OCR 有没有读错（例如 0 认成 O、8 认成 B）。

  • 点缩略图（或点右下角的 🔍）→ 全屏放大比对
  • 全屏里可以 双指捏合缩放 / 单指拖动，也可以点 ➕ 放大 / ➖ 缩小
  • 比完点「比完了」或右上角 ✕ 返回
  • 照片是识别时自动存到服务器上的，保存入库后会作为设备的铭牌照片一并归档
  1. 人工校正：
  • ⭐ SN 有候选就点候选：系统会拿同型号已录入的编号规律推断几个更可能的写法，

显示在 SN 下面（如 YLX2K4K1），点一下就替换，不用一个字一个字改。 视觉模型最容易把 L/1、O/Q、H/K 看错，这一步能省掉大半手工修改。

  • 自动纠正过会明确告诉你（「已自动去掉标签：SN1YLX22196 → YLX22196」），不会偷偷改
  • 其它字段识别不准就直接点进去改；置信度低于 60% 会标红，重点检查
  1. 补充信息：
  • 设备分类（有识别提示会自动选好）
  • ⭐ 分类专属字段：选好分类后会自动出现这个分类特有的字段。例如选「显示器」会多出 屏幕尺寸（24寸 / 27寸 下拉）、分辨率、接口类型；选「笔记本电脑」会出现 CPU / 内存 / 硬盘 / 屏幕尺寸等
  • 所属组织、使用人、存放位置、供应商、状态
  1. 点 💾 保存入库

🔁 识别不满意想重拍？ 底部有 重拍 按钮，点一下直接回到相机（不用回首页再点一次「拍照识别入库」）。

拍照预览页上的「重拍」同理。

为什么识别会更准了#

改进说明
图像分辨率 1600 → 2200px铭牌上的序列号只占几十个像素，多给点像素明显更准
送识别前先做灰度 + 对比度拉伸手机拍铭牌常偏灰、反光，拉伸后字和底分得更开（不动归档的原图）
提示词明确要求逐字符确认易混字符明确告诉模型 1/L/I、0/O/Q、8/B、5/S、2/Z、H/K 要分清，且不许「猜一个合理的」
同型号编号规律兜底同型号机器的编号长得极像（联想 ThinkCentre 全是 YLX 开头 8 位），拿档案一比就能把看错的字符纠回来
只保留取景框内的画面见下

📐 只保留取景框内的画面（省空间）#

拍照时只截取取景框里的那一块，框外的背景全部丢掉：

分辨率整帧实际保留省掉
1080×1920（常见手机竖屏）100%约 30%≈ 3.4 倍
2160×3840（4K）100%约 30%≈ 3.4 倍
1920×1080（横屏平板）100%约 27%≈ 3.7 倍

好处有两个：

  1. 省空间：归档的原图从一两 MB 降到两三百 KB，服务器磁盘和手机存储都省
  2. 识别更准：同样的像素预算集中在铭牌上，字符更清楚

📌 怎么保证不会把字裁掉：

- 取景框四周额外留了 15% 余量，铭牌稍微出去一点也能带上

- 拍完的预览页显示的就是裁好的那张图——如果发现铭牌被切了，当场点「重拍」就行

- 相机顶部提示也改成了「把铭牌放进框内（只保留框里的画面，请让字完整入框）」

用 🖼️ 从相册选图 时不裁——你选的那张图本身就是你要的，按屏幕比例硬裁反而会切掉铭牌。

保存成功后提示「已入库：资产编号」，设备出现在台账里。

⚠️ 如果 SN 已存在，会提示冲突，不会重复建两条记录。此时可以改用「扫码核对」去查那台设备。

5.2.1 📸 照片是自动归档的（不用点任何保存）#

按一次快门，系统会自动做三件事——全部默认开启，无需手动操作：

自动动作说明
① 存原图手机摄像头的完整分辨率（最高 4K）。归档进这台设备的设备详情，随时可放大看铭牌小字
② 存识别图最长边 1600px，OCR 识别和列表/详情预览用它，又快又清楚

5.3 扫码核对 / 查询#

⭐ 提醒：扫码核对和拍照入库是两条完全独立的流程，互不影响：

📷 识别入库（首页大按钮）🔎 扫码核对（底部标签）

识别时机按下快门立即处理也是按下快门才解（不自动连排扫描）
取景框26% 高（够放铭牌）按码型给形状：二维码偏方、条码偏扁（只是对位参考，解码用整个画面）

用法：先进「扫哪个」，再按快门#

  1. 点底部 🔎 扫码核对
  2. 选 扫二维码（系统印的资产码、正方形格子）或 扫条码（铭牌上的长条黑白线）
  3. 把码放进画面，按下白色大圆钮才开始识别（扫条码不用横握手机，见下方说明）
  4. 识别到资产二维码 → 直接打开该设备详情；识别到 SN → 在库里查找

⭐ 为什么一定要分开选：这不是界面上的讲究，是识别准确率的根因。

浏览器的 BarcodeDetector 是按「名单」工作的，以前一个入口同时开着二维码和七八种条码，

它每一帧都要在画面里找所有类型的候选 —— 候选越多，越容易张冠李戴或者干脆漏掉，

也就是之前反馈的「自动识别很不准确」。现在进哪个入口就只开那一种，候选少了一个数量级。

📌 不再自动连续识别了（按反馈改的）：对准之后要按一下白色圆钮才解码。

好处是不会有「画面一直在跳、识别结果反复变」的情况，也更省电。

一次没解出来，调整距离或角度再按一次即可 —— 内部会按这个码型最优的顺序多试几种切法

（二维码先取中心方形、条码先用整帧），不用手动切换。

💡 扫不出来时：先把手机拿远到 10~20cm、让整个码完整落在画面里，比贴得很近更好认。

取景框只是给你对位用的参考，程序解码时用的是整个画面，所以码稍微偏出框也没关系。

🔲 扫二维码的取景框是正方的（你提的对，二维码是方的，框就该是方的）。

以前给的是扁长条，照着框摆反而容易把码推出画面 —— 现在按屏幕短边的 68% 画一个正方形，并垂直居中。

扫条码时框会变成扁的（长条码本来就扁），两种形状是为了对位方便，不参与解码。

🧭 扫条码要不要横握手机？不用。 一维条码的一趟解码会把画面按 90° / 270° / 180° 各转一遍再解，

所以你竖着拿、横着拿、甚至铭牌是倒着贴的，程序都能认。

横着拿的好处只有一个：长条码正好铺满画面的宽边，每根黑白条踩到的像素更多 —— 更稳、更快，

但不是扫得出来的前提。二维码更不用管角度：它三个角的定位框天生就是给「任意角度」设计的

（现在也补了两趟旋转兜底，对付个别浏览器对横版画面的水土不服）。

二维码为什么以前扫不出来#

一共三个原因：一个是识别器配置，一个是「给的码不对」，一个是「快门那条路没优化」。

① 识别器的格式配置写死了。 网页内扫码用的是浏览器的 BarcodeDetector。它接受一个 formats 参数， 而这个参数是白名单过滤器——传进去就意味着「只认这几种」。旧代码一口气写死了 10 种格式， 浏览器只要有一种不支持就会报错、或者干脆什么都不返回。

对二维码而言这一步很致命：只要清单里有一个成员不被支持，整个识别器就废掉了， 表现就是「一维条码偶尔能扫、二维码完全扫不出来」。

现在改成先问浏览器支持什么，再按交集配置；问不到就干脆不限定格式（等于全开）。

② 设备详情页只给了最密的那张码。 这一条更隐蔽：码是合法的、能扫的，就是太密。 网址码 72 个字节，按接口默认的 M 级纠错要占 37×37 个模块；把它显示成 150px 时， 每一格只有 3.8 个像素。手机对着另一块屏幕拍照本来就有摩尔纹和反光， 3.8px/格基本靠运气 —— 而边上的资产编号码是 21×21，同一尺寸下每格 7.1px，一眼就过。

现在详情页把资产编号码放大到 240px 放在最上面（每格 8.9px），网址码降为备用并标注「手机自带相机用」。

③ 快门按钮走的是另一条路，没吃到前面两轮的优化。 这一条最隐蔽。 自动扫描循环是「换着姿势找」的（整帧 → 放大 → 中心方形）， 但白色大圆钮以前是直接把原始视频帧丢给识别器 —— 不裁剪、不放大、只解一次。 屏幕上那张 150px 的码，换算回 1920×1080 的视频帧里只剩几百像素， 再被浏览器内部缩一次，格子就糊成一片了。表现就是「对准了却怎么也认不出」。 现在快门会对这一帧做多趟解码（按码型挑最优顺序：二维码先取中心方形、条码先用整帧）， 每次还会放大到合适的分辨率再交给识别器。

④ 一个入口同时解所有码型，导致本来就慢而且还容易认错。 这是「不准确」的直接原因。 浏览器的 BarcodeDetector 按名单工作，以前一口气把二维码和七八种一维条码都开上， 每一帧都要在画面里找所有类型的候选。现在拆成「扫二维码」和「扫条码」两个入口， 各只开自己那一族 —— 候选少了一个数量级，准确率明显上来。

⑤ 顺带按反馈去掉了自动连续识别：以前一进页面就自动地反复解码， 结果是识别结果在眼前反复跳变、手机发烫耗电。现在改成按下圆钮才解一次， 一次没出来就调整距离换个角度再按一次，可控也省电。

⑥ 浏览器干脆认不出来时，现在由服务器兜底。 浏览器那套识别在「对着显示器拍」时上限很低： 屏幕上 150px 的码，换算回视频帧只剩几百像素，再叠上摩尔纹、视频压缩和浏览器自己的缩放， 经常整帧失手。所以现在多了一条路：手机把这一帧的中心方块转成灰度发给服务器， 由服务端自己写的解码器来认（多窗口二值化 + 定位图案几何校验 + RS 纠错，见上一节实测数据）。 这条路人手一个，iPhone 也能网页内扫码了。

另外还修掉了这些：

  • 识别区域不再按取景框裁剪。以前程序按屏幕上的取景框去裁画面，而相机画面是横版的，

手机竖屏显示时被裁掉大半，换算下来取景框只覆盖画面中间 20% 左右——你对着框摆得整整齐齐， 程序解的却是画面正中很小一块。现在改成整帧和中心方形轮着试，不再依赖框的位置。

  • 一帧只解一次码（以前一帧解两遍），中低端手机不再被拖卡。
  • 核对时扫到自己设备的网址码也算「一致」，不再明明扫对了却报不一致。

七、自动盘点：GLPI Agent 自动上报#

前面第五章的拍照识别是人工一台台录。这一章是让电脑自己报——

在每台 Windows 电脑上装一个 GLPI Agent，它会把主机名、序列号、品牌、型号、

CPU、内存、硬盘、操作系统、网卡 MAC / IP、登录用户，以及接在这台机器上的显示器的序列号和尺寸

自动报给本系统。之后不再需要举着手机拍铭牌。

7.1 它是怎么工作的（一张图看懂）#

每台电脑上的 GLPI Agent  ──①打招呼(CONTACT)──▶  本系统 /api/agent
                         ◀─②回话：用 glpi 协议、6 小时后再来─
                         ──③交盘点(INVENTORY，gzip 压缩)──▶  解析 → 落库
                                                              │
                                              出现在「自动盘点 → 待认领机器」
                                                              │
                                              你点「认领」→ 成为正式台账资产
                                                              │

⚠️ 最重要的一条设计：agent 报上来的是机器自己的序列号（如 640HP72）， 它不知道企业的资产编号（PC-2026-0017）。所以系统绝不会自动往台账里插数据—— 一律先落在「待认领」里，等你确认。这是防止台账被搞脏的关键。

7.2 三步装好#

第一步：生成上报令牌#

管理端 → 左侧 自动盘点 → 上报令牌 页签 → 生成令牌。

  • 建议按批次/区域分开建（「办公区电脑」「财务部」），以后要停用某一批就停那一个
  • 令牌只在生成时显示一次（库里只存哈希），关掉窗口就看不到了
  • agent 那边把令牌同时填进「用户名」和「密码」两个位置

第二步：在每台电脑上跑一条命令#

把项目里的 scripts\install-glpi-agent.ps1 拷到目标电脑（或用共享目录）， 用管理员身份的 PowerShell 执行：

局域网内的电脑（绝大多数，推荐）

powershell -ExecutionPolicy Bypass -File install-glpi-agent.ps1 `
  -Server "http://192.168.110.138:8080/api/agent" -Token "你的令牌"

要带回家的笔记本（走公网穿透）

powershell -ExecutionPolicy Bypass -File install-glpi-agent.ps1 `
  -Server "https://itam.dengxc.cloud:40259/api/agent" -Token "你的令牌" -UsePublic

加了 -UsePublic 后，脚本会自动从服务器把 CA 证书拉下来配好（/api/agent/ca）， 所以 TLS 校验照常开着，不需要用 no-ssl-check 那种关掉校验的将就办法。

这台电脑没有外网（先把 MSI 拷过去）

powershell -ExecutionPolicy Bypass -File install-glpi-agent.ps1 `
  -Server "http://192.168.110.138:8080/api/agent" -Token "你的令牌" `
  -MsiPath "D:\GLPI-Agent-1.19-x64.msi"

脚本会：下载官方 MSI（22MB）→ 静默安装成 Windows 服务 → 写入服务器地址与令牌 → 重启服务 → 立刻做一次盘点（不用等定时任务）。全程约 1~2 分钟。

装完屏幕上会打印下一步去哪儿看：自动盘点 → 待认领机器。

第三步：认领#

回到管理端 自动盘点 → 待认领机器：

情况系统怎么做
台账里已有这台机器（SN 对得上）排在推荐第一位，点一下就能认领。只补空字段，你人工填过的使用人、位置、备注、采购信息一律不动
台账里没有点「认领」→「新建设备并认领」，分类按机箱类型自动选（Laptop→笔记本、Desktop→台式主机、Server→服务器）
有人误报 / 是台临时机器点「忽略」，删掉这条上报副本；它之后再上报会重新出现

认领成功后：设备的「流转记录」里会留下凭据，extra 里记下机器身份（deviceid / UUID）， 以后同一台机器再上报就认得出是它。

7.3 显示器：不用再拍背面标签了#

这是最省事的一项。agent 会通过 EDID 读出接在主机上的显示器：

拿到什么说明
序列号真正的显示器 SN（如 ABH55D）
型号代号如 DJCP6（厂商内部型号串）
厂商如 Sharp Corporation
尺寸 / 生产年份从 EDID 的 description 解出来（如 32/2015 → 32 英寸、2015 年）

到 自动盘点 → 显示器 页签：

  • 认领到已有显示器资产：会按序列号优先匹配；没有 SN 的显示器资产会按型号/尺寸给出「待确认」候选
  • 新建一台显示器资产：序列号、品牌、型号、尺寸（如「32 英寸」）自动填好，备注里写明「由自动盘点识别（接在 X 上）」

⚠️ 实话实说：EDID 读取依赖显卡驱动走 DDC/CI 通道，个别显示器读不出序列号（厂商没写，或者走的是老式 VGA 接口）。

那种情况这一行会显示「EDID 未提供」，仍然需要人工补一次——但至少比每台都拍省事。

7.4 自动同步：认领之后会发生什么#

认领过的机器，之后每次上报都会自动更新这几个字段（都是"机器事实"）：

字段说明
MAC 地址 / IP 地址机器换网口、换网段会自动跟上
操作系统重装系统后自动更新
CPU / 内存 / 硬盘加内存、换硬盘后自动更新

永远不动的字段（这些是"人的决定"）：资产编号、设备分类、所属组织、使用人、 状态、采购信息、照片、备注。

想临时停掉某台机器的自动同步？在待认领列表里点它那行的「同步」旁边的开关即可

（接口是 POST /api/agent/machines/<id>/sync，auto_sync 传 false）。

7.5 关于「部分盘点」——这一条关系到数据安全#

GLPI Agent 默认大部分时候只上报变化的那几个部分（协议里叫 partial，默认 14 次里只有 1 次是全量）。 所以本系统的入库逻辑是按段合并：

这次报了什么怎么处理
全量盘点整份替换（机器换了配置，某一段没了就该没了）
部分盘点（partial: true）只覆盖这次报上来的段，没报的段原样保留

举个例子：某次只报了 CPU 段，那么软件列表、显示器、内存、硬盘的信息都还在。

要是写成"整条覆盖"，第二次上报就能把这些数据洗掉一半——这是这个功能里最容易写错的地方，

所以测试里专门钉了这条（tests/agent.js 里的「部分盘点：没报的段必须原样保留」）。

几条容易踩的：

  • agent 是"机器 → 服务器"推数据，和你在外面打开网页是两条路。内网机器不需要走穿透，

走穿透等于绕远路（数据先发到樱花服务器再绕回来），白占流量还更慢。

  • agent 的 server 只能填一个地址。填两个会导致同一份盘点执行两次、重复上报。
  • 穿透断了不会丢数据：协议规定上报失败时 agent 要保留盘点结果、按服务端给的

expiration 到期重试。内网那批更是完全不受影响。

  • 流量不用担心：一次完整盘点的 JSON 是几十 KB 量级（软件列表特别多的机器才大），压缩后更小。

7.8 只支持"电脑盘点"#

本系统只处理 inventory 这个动作（也就是电脑/服务器盘点）。agent 的 netdiscovery（网络扫描发现）、netinventory（网络设备盘点）、deploy、collect 这几种任务的报文结构完全不同，硬塞进来只会造出一堆空字段的垃圾记录， 所以服务端会明确回绝并说明（回 2xx，避免 agent 反复重试）。

需要网络设备自动发现的话，那是另一件事，得单独做 SNMP 采集。

8.2 设备分类（🗂️）#

  • 每个分类有：名称、编码、资产编号前缀、图标、主题色、专属字段
  • 资产编号前缀决定自动生成的编号，如「显示器」前缀 MON → MON-2026-0001
  • 专属字段：给该分类特有的属性，电脑端和手机端录入时都会自动出现
  • 已有设备的分类不能直接删除，需要先处理设备

专属字段支持 4 种类型

类型说明
文本自由输入
数字只能填数字
日期日期选择器

怎么加一个下拉选项（以「显示器 → 屏幕尺寸」为例）

  1. 进入 🗂️ 设备分类，找到「显示器」，点「编辑」
  2. 在「专属字段」里找到 screen_size 那一行
  3. 类型选 下拉选项，右边会出现「选项」输入框
  4. 填入 24寸, 27寸（逗号分隔）
  5. 保存

设置好后：

  • 电脑端新增/编辑显示器时，「屏幕尺寸」变成下拉框
  • 📱 手机端拍照录入选到「显示器」分类时，也会出现这个下拉框
  • 想增减尺寸，改这里的选项即可，不用改代码

系统已预置：显示器 = 24寸 / 27寸；笔记本电脑 = 13.3寸 / 14寸 / 15.6寸 / 16寸。

如果某台设备的历史值不在选项里，下拉框会把它临时保留下来，不会因为改配置而丢数据。
