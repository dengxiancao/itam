## 一、系统概览

本系统用来管理公司的 IT 资产：**设备台账、组织归属、领用交接、保修跟踪、批量导入导出**，并支持在手机上**拍照识别设备品牌与 SN 号**快速入库。

### 三个访问入口

| 入口 | 地址 | 用途 |
| --- | --- | --- |
| **管理端**（电脑） | `http://<服务器IP>:8080/` | 全部管理功能，建议用 Chrome / Edge |
| **移动端**（手机） | `https://<服务器IP>:8443/m` | 现场拍照识别、扫码核对。**必须是 https**，否则相机用不了 |
| **公网访问** | `https://itam.<你的域名>:<端口>/` | 出差在外也能用，需由管理员部署 |

> 💡 手机首次打开自签证书的地址会提示「不是私密连接」，点 **高级 → 继续访问** 即可。

### 浏览器要求

- 电脑：Chrome / Edge / 火狐 等现代浏览器（不支持 IE）
- 手机：系统自带浏览器、Chrome、Safari 均可；**相机功能要求 https**

## 二、快速上手（5 分钟）

### 第 1 步：登录

1. 打开管理端地址，会自动跳转到登录页
2. 输入管理员给你的**用户名**和**密码**
3. 勾选「记住我」可保持 30 天免登录（公共电脑请勿勾选）
4. 点「登 录」

### 第 2 步：认识界面

```
┌────────────┬──────────────────────────────────────────────┐
│  IT 资产管理 │  ☰  仪表盘          [全局搜索框]  公司 👤账号 退出 │
├────────────┼──────────────────────────────────────────────┤
│ 📊 仪表盘   │                                              │
│ 💻 设备台账 │              内容区                          │
│ 🏢 组织架构 │                                              │
│ 🗂️ 设备分类 │                                              │
│ 📑 Excel对接│                                              │
│ 🗑️ 回收站   │                                              │
│ 👥 用户管理 │                                              │
│ ⚙️ 系统设置 │                                              │
└────────────┴──────────────────────────────────────────────┘
```

- **左侧菜单**：只能看到你有权限的功能（权限由角色决定）
- **顶部搜索框**：输入资产编号 / SN / 品牌 / 型号 / 使用人，回车直接搜
- **右上角**：「账号」改自己的密码，「退出」注销登录
- **☰ 按钮**：收起/展开左侧菜单，屏幕小的时候很有用

### 第 3 步：录入第一台设备

1. 左侧点 **💻 设备台账**
2. 点右上角 **＋ 新增设备**
3. 必填项只有两个：**设备分类**、**资产编号**（留空会自动生成）
4. 建议同时填 **品牌、型号、SN 序列号**（SN 是设备的唯一身份，强烈建议填）
5. 点「保存」

> 📱 如果现场有设备实物，用手机拍铭牌录入更快，见[第五章](#五手机端拍照识别入库)。

### 第 4 步：在手机上也能用管理端

管理端已经做了手机适配，用手机浏览器打开同一个地址即可：

| 操作 | 说明 |
| --- | --- |
| **打开菜单** | 点左上角 **☰**，侧边栏从左侧滑出；点右侧灰色遮罩、按返回或选中任意菜单都会自动收起 |
| **看设备列表** | 宽表格自动变成**一张张卡片**，每个字段前面带名称，不用左右拖动 |
| **筛选** | 筛选框自动变成整行排列，手指好点 |
| **弹窗** | 从屏幕底部滑出，按钮变大，方便单手操作 |
| **搜索** | 顶栏搜索框会自动伸缩适应屏幕 |

> 分工建议：**现场录入用移动端 `/m`**（拍照识别、扫码最快）；**查看和管理用管理端**（信息最全）。
> 管理端和移动端共用同一个账号，登录一次两边都能用。

## 三、账号与权限

### 3.1 查看和修改自己的账号

点右上角 **账号**：

- 可以看到自己的用户名、姓名、角色、权限数量
- 可以改**姓名**和**密码**（改密码需要输入当前密码）
- 点「我的登录记录」可以看到自己最近的登录时间、IP、设备

> ⚠️ 修改密码后，你在**其它设备上的登录会全部失效**，需要用新密码重新登录——这是正常的安全机制。

### 3.2 四种角色能做什么

| 角色 | 适合谁 | 能做什么 |
| --- | --- | --- |
| **系统管理员** | IT 负责人 | 全部功能：设备增删改、组织分类、Excel 导入导出、回收站、**用户管理**、系统设置 |
| **资产管理员** | 资产专员 | 设备增删改、组织分类、Excel 导入导出、回收站、查看审计日志；**不能**管用户、不能改系统设置 |
| **录入员** | 现场录入人员 | 查看设备 + 新增/编辑设备（含手机拍照录入）、导出 Excel；**不能删除**设备 |
| **只读** | 领导 / 其他部门 | 只能查看仪表盘、台账、组织、分类，不能做任何修改 |

> 权限是**服务端强制校验**的：即使绕过界面直接调接口，也会被拒绝（返回 403）。

### 3.3 忘记密码怎么办

- 找**系统管理员**，在「用户管理」里点「重置密码」，会生成一个一次性随机密码给你
- 用这个密码登录后，系统会提示你立即改成自己的密码
- 如果管理员自己忘了密码，需要在服务器上运行：`node server/reset-password.js`

### 3.4 管理员：用户管理

左侧 **👥 用户管理**（仅系统管理员可见）

**新建用户**

1. 点「＋ 新建用户」
2. 填用户名（登录名）、姓名、选择**角色**、**状态**
3. 设初始密码（至少 8 位，不能纯数字/纯字母；可点 🎲 生成随机密码）
4. 保存后把用户名和密码交给对方

**常用操作**

| 操作 | 说明 |
| --- | --- |
| 编辑 | 改姓名、角色、状态、邮箱、电话；也能直接帮他改密码 |
| 重置密码 | 生成一次性随机密码，该用户**所有已登录设备立即被踢下线** |
| 解锁 | 连续输错 5 次密码会锁定 10 分钟，可在这里提前解锁 |
| 通过 | 审核自助注册的账号（待审核状态不能登录） |
| 删除 | 删除账号（该用户录入过的设备记录会保留） |

**查看登录日志**：点「📜 登录日志」可以看到谁在什么时候、从哪个 IP、用什么设备登录成功或失败。

**自助注册开关**（在 系统设置 → 企业信息 里）：

- 「允许访客自助注册」默认**关闭**（内网自用建议保持关闭）
- 开启后建议同时勾选「注册后需管理员审核」，并把默认角色设为「只读」或「录入员」

## 四、设备台账（核心功能）

### 4.1 仪表盘：一眼看全局

左侧 **📊 仪表盘**，包含：

| 区块 | 内容 |
| --- | --- |
| 顶部数字卡 | 设备总数、在用、库存/闲置、维修中、资产总值、**保修即将到期** |
| 设备状态分布 | 环形图，鼠标悬停看各类占比 |
| 分类 TOP | 各分类设备数量柱状图 |
| 品牌 TOP10 | 各品牌数量排行 |
| 最近更新 | 最近改动的 10 台设备，点击直接进详情 |
| 保修预警 | **90 天内到期或已过期**的设备清单 ⚠️ 重点看这里 |
| 最近操作记录 | 谁在什么时候改了什么设备 |

### 4.2 查设备：筛选与搜索

进入 **💻 设备台账**，顶部有一排筛选条件：

| 筛选项 | 说明 |
| --- | --- |
| 关键词 | 搜资产编号 / SN / 品牌 / 型号 / 使用人 / 工号 / IP / MAC / 位置 / 合同号 / 备注 |
| 分类 | 按设备分类过滤 |
| 组织 | 按组织过滤（**含下级组织**，选「总公司」会带出所有子部门设备） |
| 状态 | 在用 / 库存 / 闲置 / 借出 / 维修中 / 已报废 / 丢失 |
| 供应商 | 按供应商过滤 |

- 点「🔍 查询」或直接在关键词框按回车
- 点「重置」清空所有条件
- 每一列点表头无法排序（如需排序请用导出后在 Excel 里排）

### 4.3 看一台设备的全部信息

在列表里点行尾的 **查看**，弹出详情：

- **基本信息**：编号、分类、品牌型号、SN、状态、组织、使用人、联系方式、IP/MAC、系统、配置、采购与保修、金额、供应商、合同号
- **流转记录**：这台设备从创建到现在，每一次改动（谁、什么时候、把哪个字段从什么改成了什么）
- **资产二维码**：手机移动端扫码即可查到这台设备，可直接打印贴到设备上

### 4.4 新增设备

点 **＋ 新增设备**。表单分三块，**字段多少由「设备分类」决定**：

| 区块 | 内容 |
| --- | --- |
| **① 核心字段（固定 7 个）** | 资产编号、设备分类、品牌、型号、SN 序列号、所属组织、状态 —— 少一个就说不清"这是台什么设备"，所以永远显示 |
| **② 专属字段** | ⭐ **跟着「设备分类 → 专属字段」的配置走**：那个分类配了什么就在这里出现什么（含顺序、名称、是否下拉）。没配就只显示一句提示，告诉你去哪里加 |
| **③ 其他字段（折叠）** | 分类**没**点名的设备字段（使用人工号、电话、采购日期、保修到期、金额、合同号、成色、备注、IP、MAC、系统、CPU、内存、硬盘、屏幕尺寸…）收在最下面的折叠区里。**不占地方，但仍是真输入框**：已有数据能看能改，不会因为"界面上没有"而被清空 |

举例：把「台式主机」的专属字段配成只有「使用人 / 存放位置」，那么新增台式主机时就只看到
核心 7 个 + 使用人 + 存放位置，其余全在折叠区里 —— 表单短、录入快，也不会漏掉历史数据。

> 💡 **表单显示什么、导出 Excel 有哪些列，都由「设备分类 → 专属字段」这一处统一决定**
> （详见[第六章](#六excel-批量导入与导出)与[8.2](#82-设备分类)）。
> 想让「保修到期」出现在表单上？把它加到该分类的专属字段里即可（key 输入框点一下有下拉提示）。

| 说明 | 内容 |
| --- | --- |
| 资产编号 | 留空按「分类前缀-年份-流水号」自动生成，如 `MON-2026-0001` |
| SN 序列号 | 全库唯一，重复会报错 |
| 状态 | 默认「库存」；手机端录入默认「在用」 |
| 保修到期 | 填了会进仪表盘的「保修预警」 |

### 4.4.1 批量识别录入：手上是照片，一次入一批

**什么时候用它**：刚拆箱一批设备，或从仓库收回一堆机器 —— 手上**只有照片**（手机拍的、相机拍的都行），
没有表格。一台台手填太慢，走 Excel 导入又得先照着照片把字段敲进表格里，等于录两遍。

**用法**：

1. 左侧 **💻 设备台账** → 工具栏点 **📷 批量识别录入**
2. 把照片**从资源管理器直接拖进那个虚线框**（最顺手），或者点文件框**按住 Ctrl / Shift 点选**、
   在文件夹里**直接框选**一批（一次最多 100 张；超出的张数不会排队，页面上会写明还剩多少张没进来）
3. 系统**一张一张地**识别（为什么不能一起传，见下面的提示）
4. 识别完出现核对表格，每行是「照片 + 品牌 + 型号 + SN + 分类 + 组织 + 状态」：

| 你要做的 | 说明 |
| --- | --- |
| **照着左边的照片核对** | 识别只是初稿。SN 最容易看错（`L/1`、`O/Q`、`8/B`），重点看这一列 |
| 改字段 | 直接在表格里改：品牌 / 型号 / SN，逐台可改**分类、所属组织、状态** |
| 去掉不想入库的 | 把那一行最左边的勾去掉 |
| 看置信度 | 每行末尾显示识别置信度；读到倒置照片会另外标注「已转正 180°」 |

5. 确认无误 → 点右下角 **批量入库（N 台）**。入库过程中每一行依次变成「已入库 xxx」
6. 点「取消」关掉弹窗，台账会自动刷新

**各种识别结果怎么处理**：

| 情况 | 系统表现 | 你该做什么 |
| --- | --- | --- |
| 拖进来的是文件夹 / Excel | 提示「拖进来的不是图片文件」，不入队 | Excel 走 [第六章 Excel 导入](#六excel-批量导入与导出) |
| 读全了 | 状态「已读出」，默认**打勾** | 核对后直接入库 |
| 只读到品牌 / 型号，没读到 SN | 标 **没读全** | 照片对着补 SN，补完自己打勾；不补就不会入库 |
| 整治照片什么都没读出来 | 标 **识别失败** + 原因，**默认不打勾** | 点「重试 N 张」只重跑这几张（已读到的不重跑）；或换张照片 |
| 网络/服务端错误 | 同上，失败原因原样显示 | 同上 |

> ⏱ **为什么必须一张一张地传**
> 系统用的是免费视觉识别服务，**限的是「同时几个请求」，不是「一天多少次」**。
> 十张一起传上去会被服务端直接拒掉，而界面上的表现只是「没读出内容」——
> 看着像识别不准，其实是并发撞的，而且极难查。所以这里刻意做成串行：慢一点，但一定读得到。
> 十张最坏（每张都要换角度重试）大约两三分钟；满额 100 张最坏要跑 400 次识别，按十几分钟到半小时算，
> **期间别关标签页**。关掉窗口会中止还在跑的识别，已经读到的不受影响 —— 但如果已经有识别好、
> 还没入库的，系统会**先问你一句**（100 张的结果手一滑关掉就全没了，得重选一遍照片）。

> 📌 **只识别品牌 / 型号 / SN 三个字段**，其余字段（使用人、存放位置、采购日期…）统一在入库后补：
> 单台走「编辑」，一批走 **批量操作 → 交接使用人 / 转移到组织**。

> 📌 **和 Excel 导入怎么选**：手上有**照片** → 用这里；手上有别人填好的**表格** → 走
> [第六章 Excel 导入](#六excel-批量导入与导出)。别绕照片一圈。

> 📱 同样的能力手机上也有（相册一次选多张，**两端上限相同：一次最多 100 张**），见
> [5.4 一次选多张](#一次选多张批量识别入库)。

### 4.5 编辑与批量操作

**编辑单台**：列表行尾点「编辑」，改完保存。所有改动都会记进流转记录。

**批量操作**：

1. 勾选左侧复选框（表头复选框 = 全选本页）
2. 点「批量操作」下拉，选择：

| 操作 | 用途 |
| --- | --- |
| 变更状态 | 一批设备统一改成「在用 / 维修中 / 已报废」等 |
| 转移到组织 | 部门调整时整批划转 |
| 交接使用人 | 人员离职/换岗，填新使用人+工号+电话+组织，状态自动设为「在用」 |
| **⬇ 导出所选** | ⭐ **只把勾选的这几台导成 Excel**（菜单上会显示数量，如「导出所选 (7)」） |
| 删除所选 | 放进回收站（可恢复） |

> 📌 「导出所选」导出的是**你勾中的那些设备**，跟当前筛选条件、分页都没关系——
> 比如筛出「显示器」后只勾 3 台，导出的就是这 3 台。

### 4.6 删除与回收站

- 删除设备**不会真的丢**，会先进 **🗑️ 回收站**（软删除）
- 在回收站里可以：**单条恢复**、**全部恢复**、**彻底删除**（不可找回）、**清空回收站**
- 恢复时会自动检查资产编号和 SN 是否与现有设备冲突

### 4.7 导出

设备台账右上角有两个导出入口，**分得很清楚**：

| 按钮 | 导出范围 |
| --- | --- |
| **⬇ 全部导出**（右上角） | ⭐ **全部设备**，不受上方筛选条件影响 |
| **批量操作 → ⬇ 导出所选** | **只导出勾选的设备**，不限本页、跨页也认 |
| **📑 Excel 表格** 页的按钮 | 按**当前筛选结果**导出，可选分表 / 带照片 |

> 三者都是导出 .xlsx，都默认带上设备照片（图片嵌在单元格里）。
> 只想导出某个筛选范围（比如「财务部的显示器」）→ 去 **Excel 表格** 页点导出。
> 详见[第六章](#六excel-批量导入与导出)。

### 4.8 资源管理器：像 Windows 一样按组织架构找设备

左侧导航 **资源管理器** —— 操作方式和 **Windows 资源管理器一模一样**：左边是文件夹树，右边是内容区，

**操作方式（和资源管理器逐条对应）**

| 资源管理器里怎么做 | 这里就怎么做 |
| --- | --- |
| 点文件夹 | 点左边树，或**双击内容区里的文件夹** |
| 上一级 / 后退 / 前进 | 工具条的 **↑ / ← / →**；键盘 **Backspace / Alt+← / Alt+→** |
| 看当前在哪 | **地址栏**（面包屑），点任一级跳过去；点地址栏空白处可以**直接输路径**（如 `总公司\信息技术部\运维组`） |
| 选中一个 | 单击那一行 |
| 加选 / 连选 / 全选 | **Ctrl+单击** 加选 · **Shift+单击** 连选 · **Ctrl+A** 全选 · 点空白处取消 |
| 打开 | **双击**（文件夹=进入，设备=打开详情）；键盘 **Enter** |
| 右键 | 设备、文件夹、空白处各有自己的右键菜单 |
| 重命名文件夹 | 选中后按 **F2**，或右键 →「重命名」 |
| 删除 | 选中后按 **Delete**，或右键 →「删除」（设备进回收站，可恢复） |
| 刷新 | **F5**，或工具条的 ⟳ |
| 按某列排序 | 点**列头**，再点一次反向（▲▼） |
| 搜索 | 右上角搜索框，**打字即搜**（只在当前文件夹及其子文件夹里找） |
| 新建文件夹 | 空白处右键 →「新建文件夹」，或文件夹上右键 →「新建子文件夹」 |
| 详细信息 / 大图标 | 工具条最右两个按钮 |
| 拖动移动 | ⭐ **把设备拖到左边文件夹、或拖到内容区里的子文件夹上** = 改归属；拖到「未分配组织」= 清空归属 |

**快捷键一览**（和资源管理器一致）

`Enter` 打开 · `F2` 重命名 · `Delete` 删除 · `F5` 刷新 · `Backspace` 向上一级 ·
`Alt+←/→` 后退/前进 · `↑↓` 移动选择 · `Home/End` 首尾 · `Ctrl+A` 全选

**「包含子文件夹」开关**

默认**关**（和资源管理器一样：文件夹只显示自己装的东西）。勾上后，右边会把所有下级文件夹里的设备一起列出来，
状态栏会显示「包含子文件夹」，同时**左边每个文件夹上的数字也跟着变成含下级的总数**——
两边永远同一口径，不会出现"文件夹写着 12 台、点进去只有 3 台"。

**几个设计上的讲究**

- **文件夹上的数字 = 点进去看到的条数**，永远一致（这条有专门的自动化测试钉住）。
- **拖动是安全的**：只改「归属组织」这一个字段，并写进每台设备的**流转记录**（谁、什么时候、从哪挪到哪），可追溯。
- **没有分页**：一个文件夹就一屏滚到底。超过 500 台时状态栏会提示，用搜索缩小范围。
- 这里和设备台账页看的是**同一份数据**，只是两种看法。
- 窄屏（手机打开电脑版）会自动变成上下布局：树在上面限高可滚，内容区在下面。

> 小技巧：你现在有 `8-C`、`12-A`~`12-D` 几个组织挂在**顶层**。如果它们其实是某个公司下面的楼栋/区域，
> 到 **组织架构** 页把「上级组织」改一下，资源管理器里就自动变成嵌套结构。

## 五、手机端：拍照识别入库

这是本系统最省事的功能：**对着设备铭牌拍一张照，自动识别出品牌、型号、SN**，核对后一键入库。

### 5.1 手机上怎么打开

1. 手机连接**与服务器同一个 WiFi**
2. 浏览器打开 `https://<服务器IP>:8443/m`
3. 首次会提示「不是私密连接」→ 点 **高级 → 继续访问**
4. 浏览器询问是否允许使用摄像头 → 点 **允许**
5. 顶部可以填「录入人」姓名（会记进操作日志，且会被记住）

> 如果一直提示打不开相机，多半是用了 `http://` 而不是 `https://`——相机必须在 HTTPS 下才能调用。

#### 两端可以互相跳转

| 从哪 → 到哪 | 入口 |
| --- | --- |
| **电脑端 → 手机端** | 左侧菜单最下方「📱 打开移动端录入」 |
| **手机端 → 电脑端** | ⭐ 两种：① 顶栏右上角的**显示器小图标**；② 首页最下方「**回到电脑端管理后台**」 |
| 两端 → 使用手册 | 电脑端左侧菜单「使用手册」；手机端首页最下方「使用手册」 |

> 手机上只能拍照录入、扫码核对、查最近设备。**改数据、看报表、导 Excel、管账号都要回电脑端**——所以手机端特意放了两个回去的入口，不用再手敲网址。

### 5.2 拍照识别入库（完整流程）

1. 点 **📷 拍照识别入库**
2. 把设备铭牌上的 **SN 条码或文字**放在取景框内，点白色快门按钮
3. 出现照片预览，点 **🔍 识别**
   > 📸 按下快门的那一刻，系统已经**自动准备了 3 份照片**（原图 / 识别图 / 缩略图），
   > 识别成功后**自动归档到这台设备名下**，不需要你点任何保存按钮。
4. 系统自动识别并填入：

| 字段 | 说明 |
| --- | --- |
| **品牌** | 显示置信度。若显示「由 SN 前缀推断」说明是根据序列号猜的，**请核对** |
| **型号** | 同上 |
| **SN 序列号** | 关键字段，置信度最高，仍建议眼神核对一遍 |

5. ⭐ **照片就在上面，对着比一遍**：识别结果最上方是**刚拍的那张铭牌照片**缩略图，
   照片在下、字段在上，一眼就能看出 OCR 有没有读错（例如 `0` 认成 `O`、`8` 认成 `B`）。
   - 点缩略图（或点右下角的 🔍）→ **全屏放大比对**
   - 全屏里可以 **双指捏合缩放 / 单指拖动**，也可以点 **➕ 放大 / ➖ 缩小**
   - 比完点「**比完了**」或右上角 ✕ 返回
   - 照片是识别时自动存到服务器上的，保存入库后会作为设备的**铭牌照片**一并归档
6. **人工校正**：
   - ⭐ **SN 有候选就点候选**：系统会拿**同型号已录入的编号规律**推断几个更可能的写法，
     显示在 SN 下面（如 `YLX2K4K1`），**点一下就替换**，不用一个字一个字改。
     视觉模型最容易把 `L/1`、`O/Q`、`H/K` 看错，这一步能省掉大半手工修改。
   - 自动纠正过会明确告诉你（「已自动去掉标签：SN1YLX22196 → YLX22196」），不会偷偷改
   - 其它字段识别不准就直接点进去改；置信度低于 60% 会标红，重点检查
7. 补充信息：
   - **设备分类**（有识别提示会自动选好；识别猜不出来时用你配的默认分类）
   - 所属组织
   - ⭐ **分类专属字段**：选好分类后自动出现这个分类配置的字段。**使用人、存放位置**就在这里
     （出厂默认每个分类都带），此外还有分类特有的：选「显示器」会多出 **屏幕尺寸（24寸 / 27寸 下拉）**、
     **分辨率**、**接口类型**；选「笔记本电脑」会出现 CPU / 内存 / 硬盘 / 屏幕尺寸等
   - **供应商**、状态（默认「在用」）
8. 点 **💾 保存入库**

> ⚡ **想让这些下拉一打开就是你要的选项？** 下面两条一起用，基本就不用再手点了。

#### 自动记住上次填的（推荐，默认就开着）

**补充信息里的内容会被自动记住**：保存入库成功后，下次再录设备，表单会**直接按上次填好的带出来**
（设备分类、所属组织、供应商、状态，以及该分类的所有字段，比如使用人 / 存放位置 / CPU / 屏幕尺寸）。

所以录一批同部门的机器时，通常只需要改 SN 和型号，剩下的直接按「保存入库」。

| 想做什么 | 怎么做 |
| --- | --- |
| 用上次那套 | 什么都不用做，打开就是 |
| 改一项 | 直接在下拉里改（改完保存，记忆就更新成新的了） |
| 某项这次不想填 | 清空它再保存（**清空也会被记住**，下次不会再冒出来） |
| 整批换掉、从空白开始 | 点「补充信息」右上角的 **「清除记忆」**（要点两次确认，防误触） |

> 🔒 记忆存在**手机本地**，不上传服务器：多人共用一个账号时互不干扰；换手机或清了浏览器数据就没了
> （那种情况会自动回到下面的「预设默认值」）。

> ⚠️ 记忆里的值会**再校验一遍**：如果某个组织被删了、供应商改名了、下拉选项调整了，
> 失效的旧值会被忽略并回落到默认值，不会出现"看着填了其实没填"。

#### 预设默认值（第一次用、或清掉记忆后的兜底）

现场是一台接一台地录，同一批设备往往**同部门、同供应商、同状态**。
把默认值配好，之后就按「保存入库」，不用每次点那些下拉。

**全局默认值**：管理端 → **系统设置 → 手机录入默认值**

| 可以预设 | 说明 |
| --- | --- |
| 默认设备分类 | 识别能猜出来时**以识别为准**；猜不出来才用这里的默认值 |
| 默认所属组织 | 常见情况选一个部门，之后不用再点 |
| 默认供应商 | 如「易点云」 |
| 默认状态 | 默认「在用」 |

**分类字段的默认值**：管理端 → **设备分类 → 编辑 → 专属字段**

每一行最后多了一个 **「默认值」** 输入框：

| 字段类型 | 默认值怎么写 |
| --- | --- |
| 下拉选项（如屏幕尺寸） | 填**选项之一**（如 `27寸`）。填了不在选项里的值会被忽略，避免选到不存在的项 |
| 文本 / 数字 / 日期 | 直接填要预填的内容（如 `i5-13500`） |

留空 = 不预设。配好后：

- 手机上选到该分类时，这个字段**已经按默认值选好/填好**（仍然可以随时改）
- 电脑端**新增**设备时同样预填；**编辑已有设备**时不会用默认值覆盖已存的值

> 💡 **使用人 / 存放位置 想改名、想换成下拉、或者某个分类根本不想要？**
> 同样在 **设备分类 → 编辑 → 专属字段**：改「显示名」只影响界面（如把「使用人」改成「领用人」），
> 删掉整行则那个分类的录入界面就不再出现它。详见[第八章 8.2](#八组织架构与设备分类)。

> 🔁 **识别不满意想重拍？** 底部有 **重拍** 按钮，点一下**直接回到相机**（不用回首页再点一次「拍照识别入库」）。
> 拍照预览页上的「重拍」同理。

#### 为什么识别会更准了

| 改进 | 说明 |
| --- | --- |
| **图像分辨率 1600 → 2200px** | 铭牌上的序列号只占几十个像素，多给点像素明显更准 |
| **送识别前先做灰度 + 对比度拉伸** | 手机拍铭牌常偏灰、反光，拉伸后字和底分得更开（不动归档的原图） |
| **提示词明确要求逐字符确认易混字符** | 明确告诉模型 `1/L/I`、`0/O/Q`、`8/B`、`5/S`、`2/Z`、`H/K` 要分清，且不许「猜一个合理的」 |
| **同型号编号规律兜底** | 同型号机器的编号长得极像（联想 ThinkCentre 全是 `YLX` 开头 8 位），拿档案一比就能把看错的字符纠回来 |
| **倒置 / 横放 / 拍歪也能认** | 见下 |
| **只保留取景框内的画面** | 见下 |

#### 🧭 铭牌倒着拍也能认（不用把标签摆正）

以前有个不现实的要求：**标签必须正面朝上放进取景框**，一旦倒置、横放或拍歪就识别不出来。
可笔记本底部的铭牌相对取景方向本来就是反的，人还得扭着手机去对 —— 现在不用管方向了：

- 程序先看画面的**文字是横排还是竖排**（靠「墨量投影」的起伏判断），再按
  **0° → 90° → 270° → 180°** 的顺序轮着试，**哪一趟读出内容就停**。
- 所以正常朝上的照片**第一趟就命中**，不会多花时间、也不会多调一次识别服务。
- 只有第一趟什么都没读出来时才继续换角度，最坏试满 4 个方向。
- 一旦确实转了角度才读出，结果上方会写一行「照片是转过来的，已自动旋转 N° 后识别」，
  不会让你以为系统认错了字。
- 重试用的都是**同一张原图**的旋转副本，**不会重复归档**；最终存的照片始终是你按下快门的那一张。

> 提示词也同步改了：现在明确告诉识别模型「照片可能是倒的、斜的，先在心里摆正再逐字识别，
> 不要因为字是倒的就判断没有文字」。

#### 📐 只保留取景框内的画面（省空间）

拍照时**只截取取景框里的那一块**，框外的背景全部丢掉：

| 分辨率 | 整帧 | 实际保留 | 省掉 |
| --- | --- | --- | --- |
| 1080×1920（常见手机竖屏） | 100% | **约 30%** | ≈ 3.4 倍 |
| 2160×3840（4K） | 100% | **约 30%** | ≈ 3.4 倍 |
| 1920×1080（横屏平板） | 100% | 约 27% | ≈ 3.7 倍 |

好处有两个：

1. **省空间**：归档的原图从一两 MB 降到两三百 KB，服务器磁盘和手机存储都省
2. **识别更准**：同样的像素预算集中在铭牌上，字符更清楚

> 📌 **怎么保证不会把字裁掉**：
> - 取景框四周额外留了 **15% 余量**，铭牌稍微出去一点也能带上
> - 拍完的**预览页显示的就是裁好的那张图**——如果发现铭牌被切了，当场点「重拍」就行
> - 相机顶部提示也改成了「把铭牌放进框内（只保留框里的画面，字要完整入框；倒着 / 斜着也能认）」

> 用 **🖼️ 从相册选图识别** 时**不裁**——你选的那张图本身就是你要的，按屏幕比例硬裁反而会切掉铭牌。

保存成功后提示「已入库：资产编号」，设备出现在台账里。

> ⚠️ 如果 SN 已存在，会提示冲突，不会重复建两条记录。此时可以改用「扫码核对」去查那台设备。

### 5.2.1 📸 照片是自动归档的（不用点任何保存）

按一次快门，系统会自动做三件事——**全部默认开启，无需手动操作**：

| 自动动作 | 说明 |
| --- | --- |
| ① 存**原图** | 手机摄像头的完整分辨率（最高 4K）。归档进这台设备的**设备详情**，随时可放大看铭牌小字 |
| ② 存**识别图** | 最长边 1600px，OCR 识别和列表/详情预览用它，又快又清楚 |
| ③ 存**缩略图** | 最长边 320px，导出 Excel 时**直接嵌进表格单元格** |

之后**保存入库**时，这三份就自动挂到该设备名下。看照片有两个地方：

- **电脑端**：设备台账 → 点设备 → 设备详情右侧「设备照片」，点图看原图，也能「下载原图」
- **手机端**：最近设备 → 点设备 → 顶部「📸 设备照片」，点图全屏放大，也能「存到手机」

> 💡 用「🖼️ 从相册选图识别」上传时，**你选的原始文件本身就是原图**，系统照样自动归档。

#### 顺便在手机里也留一份

服务器上的照片归服务器管；如果你想在**手机本地**也有备份（发同事、离线看），系统默认就会自动存：

| 入口 | 什么时候用 | 存到哪 |
| --- | --- | --- |
| **识别成功后自动存** | ⭐ 默认开启，不用管 | 安卓「下载 / Download」，iOS「文件」App |
| 识别结果页照片下方 **💾 下载到手机** / **📤 存到相册** | 补存、或想进相册 | 下载同上；「存到相册」会打开**系统分享面板**，在里面选「存储图像 / 保存到照片」 |
| 设备详情 **💾 存到手机** | 事后想再存一张 | 同「下载」 |

**文件名自动带 SN 和时间**，例如 `IT资产铭牌_3TLF261_20260918-1128.jpg`，事后在文件管理器里一搜就能对上台账。

**关掉手机端自动存**：手机端首页最下方「💾 照片备份到手机」卡片里把开关关掉即可（只影响这台手机）。

**想进手机相册（而不是「文件」）**：
- iOS：用 **📤 存到相册** → 选「存储图像」；或在照片上**长按** → 选「存储到照片」
- 安卓：用 **📤 存到相册** → 选相册类应用；或在照片上**长按** → 选「下载图片」

> 📌 浏览器不允许网页「偷偷」往相册写文件，所以第一次会弹一次「是否允许下载多个文件」的询问，
> 点允许之后就安静了。如果某次自动保存没反应，点一下照片下方的 **💾 下载到手机** 即可。

### 5.3 扫码核对 / 查询

⭐ **提醒：扫码核对和拍照入库是两条完全独立的流程**，互不影响：

| | 📷 识别入库（首页大按钮） | 🔎 扫码核对（底部标签） |
| --- | --- | --- |
| 干什么 | 拍铭牌 → OCR 认品牌/型号/SN → **新建一台设备** | 扫二维码/条码 → **查出已有设备** |
| 入口 | 一个大按钮 | **两个**：扫二维码 / 扫条码，各管一类 |
| 识别时机 | 按下快门立即处理 | **也是按下快门才解**（不自动连排扫描） |
| 取景框 | 26% 高（够放铭牌） | 按码型给形状：二维码偏方、条码偏扁（**只是对位参考**，解码用整个画面） |

#### 用法：先进「扫哪个」，再按快门

1. 点底部 **🔎 扫码核对**
2. 选 **扫二维码**（系统印的资产码、正方形格子）或 **扫条码**（铭牌上的长条黑白线）
3. 把码放进画面，**按下白色大圆钮**才开始识别（扫条码不用横握手机，见下方说明）
4. 识别到资产二维码 → 直接打开该设备详情；识别到 SN → 在库里查找

> ⭐ **为什么一定要分开选**：这不是界面上的讲究，是识别准确率的根因。
> 浏览器的 `BarcodeDetector` 是按「名单」工作的，以前一个入口同时开着二维码和七八种条码，
> 它每一帧都要在画面里找所有类型的候选 —— 候选越多，越容易张冠李戴或者干脆漏掉，
> 也就是之前反馈的「自动识别很不准确」。**现在进哪个入口就只开那一种**，候选少了一个数量级。

> 📌 **不再自动连续识别了**（按反馈改的）：对准之后要**按一下白色圆钮**才解码。
> 好处是不会有「画面一直在跳、识别结果反复变」的情况，也更省电。
> 一次没解出来，调整距离或角度再按一次即可 —— 内部会按这个码型最优的顺序多试几种切法
> （二维码先取中心方形、条码先用整帧），不用手动切换。

> 💡 **扫不出来时**：先把手机**拿远到 10~20cm**、让整个码完整落在画面里，比贴得很近更好认。
> 取景框只是**给你对位用的参考**，程序解码时用的是整个画面，所以码稍微偏出框也没关系。

> 🔲 **扫二维码的取景框是正方的**（你提的对，二维码是方的，框就该是方的）。
> 以前给的是扁长条，照着框摆反而容易把码推出画面 —— 现在按屏幕短边的 68% 画一个正方形，并**垂直居中**。
> 扫条码时框会变成扁的（长条码本来就扁），两种形状是为了对位方便，不参与解码。

> 🧭 **扫条码要不要横握手机？不用。** 一维条码的一趟解码会把画面按 **90° / 270° / 180°** 各转一遍再解，
> 所以你竖着拿、横着拿、甚至铭牌是倒着贴的，程序都能认。
> 横着拿的好处只有一个：长条码正好铺满画面的宽边，每根黑白条踩到的像素更多 —— **更稳、更快**，
> 但**不是扫得出来的前提**。二维码更不用管角度：它三个角的定位框天生就是给「任意角度」设计的
> （现在也补了两趟旋转兜底，对付个别浏览器对横版画面的水土不服）。

#### 系统生成的资产二维码，长什么样

设备详情页和「打开二维码」弹窗都会给码，一共两种：

| | 内容 | 规格 | 用在什么场合 |
| --- | --- | --- | --- |
| ⭐ **大码** | **资产编号**（如 `MON-2026-0010`） | 版本 1 · **21×21 模块** | 网页内「扫码核对」扫这个，模块最少、最好扫，也不依赖手机能否访问服务器地址 |
| **小码** | 网址 `https://.../m/#/device/xxx` | 版本 5 · **37×37 模块**（密得多） | 手机**自带相机**扫这个，直接打开设备页；网页内扫码同样认 |

> ⚠️ **手机上「设备详情」页也是两个码都给**，而且把**资产编号码放大到 240px** 放在最上面：
> 21 模块在 240px 下每格约 8.9 像素，对着屏幕拍也稳；网址码只有 37 模块、
> 每格约 3.8 像素，是**全系统最密的码**，只适合手机自带相机（会自动对焦拉近）。
> 所以看到详情页别急着扫下面那个小码 —— 先扫上面那个大的。

两种码手机端都支持：扫到**资产编号**走 `/devices/lookup`（该接口同时匹配 SN 和资产编号）查设备；
扫到**网址码**直接从 `#/device/<设备号>` 里取出设备号跳转，连服务器都不用问。

> 📌 贴在设备上的标签，建议**印短码 + 把资产编号印成文字**，双保险。

#### 二维码为什么以前扫不出来

一共三个原因：一个是识别器配置，一个是「给的码不对」，一个是「快门那条路没优化」。

**① 识别器的格式配置写死了。** 网页内扫码用的是浏览器的 `BarcodeDetector`。它接受一个 `formats` 参数，
而这个参数是**白名单过滤器**——传进去就意味着「只认这几种」。旧代码一口气写死了 10 种格式，
浏览器只要有一种不支持就会报错、或者干脆什么都不返回。

对二维码而言这一步很致命：**只要清单里有一个成员不被支持，整个识别器就废掉了**，
表现就是「一维条码偶尔能扫、二维码完全扫不出来」。

现在改成**先问浏览器支持什么，再按交集配置**；问不到就干脆不限定格式（等于全开）。

**② 设备详情页只给了最密的那张码。** 这一条更隐蔽：码是合法的、能扫的，就是**太密**。
网址码 72 个字节，按接口默认的 M 级纠错要占 **37×37 个模块**；把它显示成 150px 时，
每一格只有 3.8 个像素。手机对着**另一块屏幕**拍照本来就有摩尔纹和反光，
3.8px/格基本靠运气 —— 而边上的资产编号码是 21×21，同一尺寸下每格 7.1px，一眼就过。

**现在详情页把资产编号码放大到 240px 放在最上面**（每格 8.9px），网址码降为备用并标注「手机自带相机用」。

**③ 快门按钮走的是另一条路，没吃到前面两轮的优化。** 这一条最隐蔽。
自动扫描循环是「换着姿势找」的（整帧 → 放大 → 中心方形），
但**白色大圆钮**以前是直接把原始视频帧丢给识别器 —— 不裁剪、不放大、**只解一次**。
屏幕上那张 150px 的码，换算回 1920×1080 的视频帧里只剩几百像素，
再被浏览器内部缩一次，格子就糊成一片了。表现就是**「对准了却怎么也认不出」**。
现在快门会对这一帧做多趟解码（按码型挑最优顺序：二维码先取中心方形、条码先用整帧），
每次还会放大到合适的分辨率再交给识别器。

**④ 一个入口同时解所有码型，导致本来就慢而且还容易认错。** 这是「不准确」的直接原因。
浏览器的 `BarcodeDetector` 按名单工作，以前一口气把二维码和七八种一维条码都开上，
每一帧都要在画面里找所有类型的候选。现在拆成**「扫二维码」和「扫条码」两个入口**，
各只开自己那一族 —— 候选少了一个数量级，准确率明显上来。

**⑤ 顺带按反馈去掉了自动连续识别**：以前一进页面就自动地反复解码，
结果是识别结果在眼前反复跳变、手机发烫耗电。现在改成**按下圆钮才解一次**，
一次没出来就调整距离换个角度再按一次，可控也省电。

**⑥ 浏览器干脆认不出来时，现在由服务器兜底。** 浏览器那套识别在「对着显示器拍」时上限很低：
屏幕上 150px 的码，换算回视频帧只剩几百像素，再叠上摩尔纹、视频压缩和浏览器自己的缩放，
经常整帧失手。所以现在多了一条路：手机把这一帧的中心方块转成灰度发给服务器，
由服务端自己写的解码器来认（多窗口二值化 + 定位图案几何校验 + RS 纠错，见上一节实测数据）。
这条路人手一个，**iPhone 也能网页内扫码了**。

另外还修掉了这些：

- **识别区域不再按取景框裁剪**。以前程序按屏幕上的取景框去裁画面，而相机画面是横版的，
  手机竖屏显示时被裁掉大半，换算下来取景框只覆盖画面中间 20% 左右——**你对着框摆得整整齐齐，
  程序解的却是画面正中很小一块**。现在改成整帧和中心方形轮着试，不再依赖框的位置。
- **一帧只解一次码**（以前一帧解两遍），中低端手机不再被拖卡。
- **核对时扫到自己设备的网址码也算「一致」**，不再明明扫对了却报不一致。

#### 手机浏览器扫不了码？现在有服务端兜底了

以前网页内扫码只能靠浏览器自带的 `BarcodeDetector`，**iPhone 的 Safari 没有开放这个能力**（不是系统坏了），
所以那时只能劝你「用手机自带相机扫」。

现在**二维码入口在 iPhone 上也能用**：浏览器解不出来时，手机把这一帧画面转成灰度图发给服务器，
由服务端自己的解码器来认（系统内置，不需要联网到外部服务）。

| 办法 | 怎么做 |
| --- | --- |
| ⭐ **直接按圆钮** | 浏览器认不出时自动转服务端解码，稍等一下就有结果。iPhone / Safari / 安卓拍屏幕都走这条路 |
| **手动输入** | 本机没有扫码能力、服务端也没认出这一帧时，页面会直接给手动输入框，输 SN 或资产编号一样能查 |
| **用手机自带相机** | 扫设备上的资产二维码 → 打开 `/m/#/device/xxx` → 直接进这台设备的详情页 |
| **换个浏览器** | 安卓 **Chrome / Edge** 有网页内识别能力，快一点（省掉一次上传） |

> 服务端解码只做**二维码**（资产码、网址码）。一维条码（铭牌上的长条码）仍然依赖浏览器能力，
> iPhone 上请改用二维码入口，或用「手动输入」照抄铭牌上的 SN。

服务端解码器实测：真实资产码在「1080×1920 相机帧 + 摩尔纹 + 失焦 + 噪声 + 光照不均 + 倾斜」的拍屏幕场景下，
屏幕上 **120~260px 全部认出**，每次约 **15~50 毫秒**；连最密的网址码（37×37 模块）在 150px 也能认。

#### ⚠️ 别在「电脑端页面」上扫码

**这是最容易被忽略的一条，也是扫码反复失败的常见原因。**

管理端页面（地址栏里没有 `/m` 的那个）是给电脑用的。用手机浏览器打开它时，即使它「看起来能显示」，
**这个页面本身也扫不了码** —— 请看清楚地址栏：

| 地址长什么样 | 这是什么 | 能扫码吗 |
| --- | --- | --- |
| `https://…/m` 或 `https://…/m/#/scan` | **手机版** | ✅ 能，点「扫二维码 / 扫条码」 |
| `https://…/` `https://…/#/devices` | **电脑端页面** | ❌ 不能，扫码会一直提示认不出来 |

在电脑端页面点「打开二维码」，弹窗里会**主动弹一条橙色提示**告诉你在手机上打不开摄像头，并给两个出口：

| 办法 | 怎么做 |
| --- | --- |
| ⭐ **用手机自带相机扫** | 直接扫弹窗里的码 → 手机自带相机 → 直接跳到这台设备的手机版详情页 |
| **切到手机版扫码核对** | 点弹窗左下角的 **「用手机版扫码核对」** 按钮，直接跳到 `/m#/scan` |
| **把码印出来** | 点 **「打印标签」** → 打印成纸质标签贴到设备上，之后用手机版扫码核对对着实体标签扫（**盘点最稳的一条路**） |

> 📌 为什么电脑端页面扫不了？不是相机坏了、也不是码坏了。**历史版本里这个页面的 mobile viewport 参数不全**，
> 手机浏览器不认它是响应式页面，会按桌面 980px 排版再整体缩小 —— 屏幕上的二维码跟着被缩小、
> 摄像头预览带只剩一百多像素高还被拉伸满屏（看着近乎全黑），自然怎么也认不出来。
> 现在 viewport 已补全，页面在手机上会正常排版；**但仍建议优先用手机版（`/m`）扫码**，
> 因为手机版才是为这个流程设计的界面。

#### 📏 对着屏幕拍二维码，尺寸是硬指标

如果你确实需要在手机上看电脑端页面的二维码（比如同事在旁边，你帮他扫），
**码必须够大**。一条实测出来的经验线：

| 每格像素 | 结果 |
| --- | --- |
| < 4 px/格 | 基本靠运气 |
| 4 ~ 5 px/格 | 偏紧，要贴很近、手还不能抖 |
| **≥ 6 px/格** | 稳，15~20cm 随手一拍就过 |

资产编号码是 **21×21 模块**，加上两侧各 3 格留白共 27 格。
所以它显示到 **250px 时每格约 9.3px**（稳）；而**只显示 160px 时每格才 5.9px，就属于"偏紧"那一档，扫不出来是真扫不出来**。

> 现在「资产二维码」弹窗已经把**主码放大到 250~320px**（按屏幕宽度自动选），
> 并且**窄屏时让它独占一行** —— 之前主码和备用网址码并排挤在一个 flex 里，
> 窄屏会被压到 160px 左右，这正是「怎么按快门都认不出」的直接原因。
>
> **弹窗里就该扫上面那张大的（资产编号），扫出来才对得上。**
> 下面那张小的网址码是 37×37 模块，密得多，**只建议用手机自带相机扫**，
> 别用 App 里的「扫二维码」对着屏幕拍它 —— 模块太密，10~20cm 也很难对上焦。

> 📌 **二维码里放的地址必须是手机能访问的**。管理端点「打开二维码」时可以选地址：
> 手机连同一个 WiFi 就选**局域网**，手机在外面就选**公网地址**。
> 系统会自动把 `127.0.0.1` 换掉，不会生成一个只有服务器自己打得开的码。

**核对一致性**：在设备详情页点「✅ 扫码核对这台设备」，再扫一次 SN，系统会告诉你**扫描值与台账值是否一致**，并把核对结果记进流转记录——适合盘点时用。

### 5.4 从相册选图识别

没有摄像头权限、或想用已经拍好的照片时：首页点 **🖼️ 从相册选图识别**，选**一张**铭牌照片即可识别
（不需要相机权限，走的是和拍照完全一样的识别链路）。

#### 一次选多张：批量识别入库

一次拍了一叠铭牌（比如刚拆箱十台显示器），不用一张张来：首页点 **📋 批量识别入库**，
在相册里**一次勾选多张**（一次最多 100 张；选多了不会排队，页面上会写明还剩多少张没进来），然后：

1. 屏幕上显示进度「已识别 3 / 10」，**一张一张地**识别
2. 识别完进入**核对页**：每张照片旁边有品牌 / 型号 / SN 三个输入框，**照着照片核对并改错**
3. 页面下方选 **本批统一设置**（设备分类、所属组织、分类专属字段、供应商、状态 —— 整批一起用这一套）
4. 勾选要入库的（读全的默认已勾），点 **批量入库（N 台）**
5. 全部顺利入库后**自动回到首页**；如果还有没入库的（没读全 / 识别失败 / 你没勾的），
   **会留在核对页**，方便你接着补

| 情况 | 系统的处理 |
| --- | --- |
| 某张没读到 SN | 标成 **没读全**，**默认不勾**（没有 SN 的设备录进去也查不着）。补上 SN 再勾，或点右上角「全选 / 全不选」 |
| 某张彻底失败（网络 / 服务端问题） | 标成 **识别失败** 并写明原因，点「重试 N 张」只重跑这几张；其余已读到的不重跑 |
| 有几张不想入库（比如拍到了桌上的其他东西） | 把它的勾去掉就行 |
| 中途想退出 | 点底部 **退出批量识别**。如果已经有**识别好、还没入库**的，会先问一句「还有 N 张没入库」—— 点「放弃」才真的走，点「继续核对」就留在原处，已经改过的内容不会丢 |

> ⏱ **和电脑端一样，一次只传一张**。免费识别服务限的是并发数，一起传会被拒，
> 界面上只会看到「没读出内容」。串行慢一点，但一定读得到 ——
> 所以识别期间**别锁屏、别切走浏览器**。

> 💡 十张照片最坏情况（每张都要换角度重试）大约两三分钟。上限 100 张是给「一层楼的机器一次拍完」
> 这种整批场景留的，**不是建议你每次都拍满** —— 满额最坏要十几到几十分钟，而且屏幕得全程亮着。
> 一次拍二三十张仍然是更稳的用法。

> 📌 批量页里的分类专属字段用 `bt_` 打头、单张结果页用 `mt_`，两者**不会互相抢输入框** ——
> 你不用担心在这边改了值那边跟着变。

### 5.5 最近设备

底部 **🗂️ 最近设备** 列出最近更新的 50 台设备，点进去看详情，省得回电脑上查。

### 5.6 手机端常见问题

| 现象 | 解决 |
| --- | --- |
| 点拍摄没反应 / 提示需要 HTTPS | 必须用 `https://` 打开；或先用「从相册选图识别」（相册不需要相机权限） |
| 批量识别到一半卡住不动 | 一张一张地传是故意的（并发会被上游拒）。等到当前那张出结果就行；实在卡住就「退出批量识别」重来，已读到的不丢 |
| 批量识别很慢 | 十张最坏约两三分钟（每张可能要换 4 个角度重试）。识别期间别锁屏、别切走浏览器 |
| 批量里某张老是「没读全」 | 那张照片可能反光 / 太糊 / 拍歪了。单张重拍后不用重开整批 —— 直接在核对页手填 SN，或者用单张流程补录这一台 |
| 提示「相机权限被拒绝」 | 浏览器地址栏左侧图标 → 把「摄像头」设为允许，刷新重试 |
| 识别结果不准 | 拍照时让铭牌填满取景框、光线充足、避免反光；**对着结果页顶部的照片再核对一遍**，必要时点开放大 |
| 结果页顶部的照片打不开 | 说明这次识别没有保存图片（或服务器上的文件被清理）；识别字段仍然可用，重拍一次即可恢复 |
| 照片太糊看不清 | 点缩略图全屏后两指放大；还是看不清就重拍，让手机离铭牌近一点并对上焦 |
| 想存到手机相册 | 识别结果页点「📤 存到相册」→ 选「存储图像」；或长按照片选「存储图像 / 下载图片」 |
| 自动保存没生成文件 | 部分浏览器会拦截「自动下载」。点照片下方的 **💾 下载到手机** 手动存一次；若之前点过「拒绝」，去浏览器设置里允许本站下载 |
| 不想自动存到手机 | 首页「💾 照片备份到手机」卡片里关掉开关 |
| 提示「SN 已存在」 | 该设备已录过，用「扫码核对」查询即可 |
| 上传很慢 / 卡住 | 系统已自动把照片压缩到最长边 1600px；若仍慢，检查手机与服务器是否同一 WiFi |
| 打开是乱码或样式错乱 | 强制刷新（下拉刷新），或换 Chrome 浏览器 |

## 六、Excel 批量导入与导出

左侧 **📑 Excel 表格**。

### 6.1 导出设备台账（一次性快照）

> 💡 **界面上的「?」小圆点**：鼠标悬停或点一下，会弹出这个设置/按钮的完整说明。
> 长解释都收在里面了，所以按钮上只留几个字——看不明白就点那个「?」。


在左侧 **📑 Excel 表格** 页，点第 ① 张卡上的「**导出 Excel 文件**」。卡片上先选**导出范围**，再点按钮：

| 导出范围 | 默认 | 说明 |
| --- | --- | --- |
| **全部设备** | ⭐ 选中 | 导出台账里的**所有**设备 |
| **只导出设备台账当前的筛选结果** | | 只导你在设备台账页筛出来的那部分。**只有设备台账确实设了筛选条件时才出现**，旁边会写明筛的是什么、共多少台 |

> ⚠️ **默认是「全部设备」，不受设备台账页设过的筛选影响。**
> 想只导筛出来的那部分，得**主动**选第二项——这样就不会再出现「本想导全表，结果拿到一份只有「台式主机」一张表的文件」。

折叠区「**导出选项**」里还有三个勾选：

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| **按分类分表** | ✅ 开 | ⭐ 主机、显示器、笔记本… **各自一个工作表**，另附一张「汇总」页（数量/占比/资产总值/对应表名） |
| **含照片** | ✅ 开 | 关掉后文件小得多（照片不嵌进单元格） |
| **含说明页** | ✅ 开 | 附带「字段说明 / 设备分类 / 组织架构」三张辅助表 |

设备台账页右上角还有两个入口：

| 入口 | 导出什么 |
| --- | --- |
| **⬇ 全部导出** | **全部**设备（同样不受上方筛选影响） |
| **批量操作 → 导出所选** | 只导出**勾选**的那几台 |

导出的工作表：

| 模式 | 工作表 |
| --- | --- |
| 分表 | `汇总` + 每个分类一张表（如 `台式主机`、`显示器`）+ `字段说明`、`设备分类`、`组织架构` |
| 单表 | `设备台账` + `字段说明`、`设备分类`、`组织架构` |

#### 📸 设备照片会一起导出（默认开启）

每张明细表的**最后两列**就是照片：

| 列 | 内容 |
| --- | --- |
| **照片** | ⭐ 图片**直接嵌在单元格里**，打开就能看到，不用点链接 |
| **原图链接** | 可点击的「打开原图」—— 指向**原图**（看得清铭牌的那张）；万一某台设备没有单独存原图，就退回压缩图，所以这一列**不会是空的** |

例如显示器那张表的列尾就是：

```
… 分辨率 | 接口类型 | 照片 | 原图链接
```

> 📌 以前这里是「照片链接」和「原图链接」**两列**，但两列只是同一张照片的两个尺寸版本，
> 看上去像重复了两遍，所以合并成**一列**，只保留原图链接。

> 🔗 **链接地址是「大家都能打开」的那个**：即使你是在服务器本机用 `127.0.0.1` 打开后台导出的，
> 链接也会自动写成**局域网 IP**（如 `http://192.168.1.100:8080/...`），换台电脑照样打得开。
> 想固定成某个地址（比如公网域名），去 **系统设置 → 企业信息 → 外部访问地址** 填一下即可。

> 💡 行高会自动撑大让图放得下。如果设备很多导致文件偏大，把「导出选项」里的 **含照片** 取消勾选即可。

#### 导出的文件太大 / 下载很慢？

早期录入的设备（缩略图功能上线之前）只有一张 1600px 的大图，每张约 150 KB，几十台就是好几 MB。

**Excel 表格** 页有一个 **补缩略图** 按钮：点一下，浏览器会批量把这些老照片缩成 320px 小图回传，
之后导出的体积能降到**十分之一**左右（30 台从 4.5 MB → 约 0.6 MB），下载也快得多。

> 新拍的照片本来就自带缩略图，不用管这个按钮。

> 只导出了链接没图？说明那台设备的照片文件超过了 400 KB 的嵌入上限（没有缩略图的旧设备会这样），
> 链接照样可用；点上面的「补缩略图」就能让它们也显示成图片。

#### 快照 vs 实时链接：照片怎么选

**照片能自动更新** 和 **表格里直接看到图** 这两件事，在 Excel 里没法同时做到，选一个：

| 你的需求 | 用哪个 | Excel 里的照片长什么样 |
| --- | --- | --- |
| 表格里**直接看到图**，不介意手动更新 | **按分类分表** | 图片嵌在单元格里 |
| 数据**自动更新**，照片点开看 | **🔄 实时数据链接** | 「打开原图」超链接，点一下浏览器打开 |
| **两个都要** | 实时链接 + 自己加一列公式 | 加 `=IMAGE(原图链接单元格)`（Excel 365 / 较新版 WPS 支持），刷新时图会跟着变 |

**Excel 表格** 页上有一张对照表，随时可以看。

> ⚠️ 导出的是**快照**，导完就固定了。想让数据自动更新，看下一节。

#### 每个分类的表**只带自己的字段**（列数由「设备分类」说了算）

导出不是把所有字段都铺上去，而是**按每个分类在「设备分类 → 专属字段」里的配置出列**：

| 列 | 内容 |
| --- | --- |
| **核心列（固定 7 列，任何分类都有）** | 资产编号、设备分类、品牌、型号、SN 序列号、所属组织、状态 |
| **其余列** | **分类里配了什么就出什么**：使用人 / 存放位置 / 采购日期 / 保修到期 / 采购金额 / 供应商 / 合同号 / 成色 / 备注 / CPU / 内存 / 硬盘 / 操作系统 / IP / MAC / 屏幕尺寸，以及分类自定义列（分辨率、接口类型、打印类型、端口数、机柜位、IMEI…） |
| 照片列 | 固定追加在最后（照片 / 原图链接） |

举例：**「台式主机」只配了「使用人 / 存放位置」→ 那张表就是 9 列**（7 核心 + 2），
不会再有 CPU、内存、硬盘、使用人工号、采购日期这些没配的列。

| 分类配置 | 导出列数 |
| --- | --- |
| 只配「使用人、存放位置」 | **9 列** |
| 加配「CPU、内存、硬盘、操作系统」 | 13 列 |
| 显示器配「使用人、存放位置、屏幕尺寸、分辨率、接口类型」 | 12 列 |

> 💡 **想让某个分类多导一列？** 去 **设备分类 → 编辑 → 专属字段** 加一行就出现了（key 输入框点一下有下拉提示）。
> 反过来，不想要的列就在那里删掉 —— **表单上显示什么、导出有哪些列，都由这一处统一决定**。

> 📌 单表导出（不拆工作表）也一样：列按**这批数据里真正出现的分类**取，只导显示器就不会带上 CPU。

> ⚠️ 导出的是**快照**，导完就固定了。想让数据自动更新，看下一节。

> 📄 **导入模板是另一回事**：模板是给你填的表，所以它仍然把**所有可填的字段**都列出来（列更全），
> 填哪些算哪些。导出才做裁剪。

### 6.2 🔄 让 Excel 自己跟着更新（配一次，以后一直有效）

**痛点**：每次都要重新导出很麻烦。

**解法**：把台账接成 Excel 的**数据源**，之后**打开文件就是最新数据**，不用再导出。
在 **Excel 表格** 页第 ③ 张卡（「让 Excel 自己跟着更新」）里，就三步：

#### 第 1 步：这个 Excel 文件会在哪台电脑上用？

点一个就行，系统已经帮你选好了推荐项（打了「推荐」标签那个）：

| 选项 | 什么时候选 |
| --- | --- |
| 就在这台电脑上用 | Excel 和本系统开在**同一台电脑**上（最快） |
| **在办公室其他电脑上用** ⭐推荐 | 文件会在办公室**别的电脑**上打开（大多数情况选这个） |
| 在外网 / 家里用 | 电脑不在公司、得走公网访问 |

> 这一步选错了的表现是 Excel 提示「**无法获取数据**」——换一个、重新复制链接即可。

#### 第 2 步：点一下，链接就复制好了

两个按钮，按你想要的**结果**选（不用管它内部是什么格式）：

| 按钮 | 你会得到 |
| --- | --- |
| **复制链接：全部设备放一张表** | 一张表，所有设备都在里面。第一次用建议先试这个 |
| **复制链接：每个分类各一张工作表** | 「台式主机 / 显示器 / 打印机…」**各占一张工作表**，一次配好 |

> 链接里自带**只读口令**：别人拿到它只能看台账字段，看不到密码和密钥，也改不了任何数据。

#### 第 3 步：粘到 Excel / WPS 里

| | 步骤 |
| --- | --- |
| **Excel** | ① 菜单 **数据** → **获取数据** → **自其他源** → **自网站**<br>② 粘贴链接 → 确定<br>③ 弹出的小窗口里出现表格 → 选 **Table** → 点 **加载** |
| **WPS** | ① 菜单 **数据** → **获取数据** / **自网站**<br>② 粘贴链接 → 确定<br>③ 在表格列表里选要的表格 → **导入** |

**让它自动刷新**：在生成的数据上右键 → **属性** → 勾选

- ☑ 打开文件时刷新数据
- ☑ 每 30 分钟刷新一次（按需调整）

配置一次，以后打开就自动是最新的。

#### 表格报「无法获取数据」怎么办

按顺序做这三件事，基本都能解决：

1. **把链接粘到浏览器地址栏**回车。能看到一张表格 → 链接没问题，是取数方式的问题（做第 3 条）；
   打不开 → 是第 2 条的问题。
2. **回页面换一个「这个 Excel 文件会在哪台电脑上用」**，重新复制链接再试。
3. **WPS 必须用网页表格格式**——第 2 步复制出来的默认就是它。WPS 的「自网站」不认 CSV，
   粘 CSV 链接一定报「无法获取数据」。

> 什么时候才需要 CSV？Excel（不是 WPS）里希望日期/金额是真正数字类型时。
> 页面「出问题了」折叠区里有一个「复制 CSV 链接」按钮，代价是纯数字 SN 可能变成科学计数法。

#### 只想同步某一个分类 / 想让照片显示出来

| 想做 | 怎么做 |
| --- | --- |
| 只同步一个分类 | 展开第 ③ 张卡里的 **「只想同步某一个分类」**，每个分类各有一条链接，粘到不同工作表即可 |
| 看某个分类有多少台 | 同上，那一列写着每个分类的设备数量 |
| **让照片显示在单元格里** | 导入后自己加一列，填 `=IMAGE(原图链接那一格)`（Excel 365 / 较新版 WPS 支持），刷新时图片跟着变 |
| 想让照片**一开始就嵌在文件里** | 用第 ① 张卡的「导出一份 Excel 文件」（快照，不自动更新，但照片直接嵌好、发给谁都能看） |

#### 几点说明

| 事项 | 说明 |
| --- | --- |
| 数据范围 | 只读，只包含设备台账字段，**不含任何密钥或账号信息** |
| 列的多少 | **按分类走**：每个分类的表只带该分类配置的字段（显示器不会出现 CPU/内存/硬盘，主机不会出现屏幕尺寸），和 6.1 的分表导出一致 |
| 「全部设备」那一张 | 跨分类的汇总视图，保留**完整列**，方便一眼看全 |
| 原图链接 | 单元格里是可点击的「**打开原图**」（点一下浏览器打开图）。用的是局域网地址或你设置的「外部访问地址」，不会写成 `127.0.0.1`，所以同网段的电脑都能打开 |
| 链接安全 | 链接自带只读口令；**点「重置链接」可让旧链接立即失效**（原图链接是同一套口令） |
| 什么时候该重置链接 | 换电脑/换网络后怎么都取不到数，或者链接被发到了不该发的地方 |
| 想改数据 | 实时链接是**只读**的。批量改数据用导入功能（见 6.5） |
| 导出点了没反应 / 浏览器报「网络问题」 | 系统已改成「先由页面把文件取回来、再触发下载」，失败时会明确告诉你原因。若仍失败，试试取消 **含照片** 缩小体积，或点 **补缩略图** |

### 6.3 下载导入模板

点 **⬇ 下载导入模板**，得到 `IT资产导入模板_日期.xlsx`，包含 5 个工作表：

| 工作表 | 说明 |
| --- | --- |
| **设备台账** | ⭐ **数据填在这里**，从第 3 行开始，表头（第 2 行）不要改 |
| 填写示例 | 两条示例，**仅供参考格式，本页不会被导入** |
| 字段说明 | 每个字段的填写要求 |
| 设备分类 | 已有分类名称（导入时按名称匹配） |
| 组织架构 | 已有组织（支持写全路径） |

### 6.4 填写规则

| 列 | 怎么填 |
| --- | --- |
| 资产编号 | 可留空（自动生成）。填写时必须全库唯一 |
| **设备分类** | 填分类名称，如「显示器」。**不存在的分类会自动创建** |
| 品牌 / 型号 | 如 Dell / U2723QE |
| **SN 序列号** | 建议必填；重复的 SN 不会重复建记录（会走更新） |
| **所属组织** | 支持三种写法：`信息技术部`、`总公司 / 信息技术部`、`总公司 / 信息技术部 / 运维组` |
| 状态 | 从下拉选择：在用 / 库存 / 闲置 / 借出 / 维修中 / 已报废 / 丢失 |
| 采购日期 / 保修到期 | 支持 `2024-03-15`、`2024/3/15`、`2024年3月15日`，Excel 日期格式也行 |
| 采购金额 | 纯数字，不要带「元」或货币符号 |
| 供应商 | 从下拉选择（选项在 系统设置 → 企业信息 里维护） |
| 成色 | 建议 A / B / C |

**小技巧**

- 表头**可以换位置、也可以用同义词**（如「SN」「序列号」「Service Tag」都能识别）
- 多余的列会被忽略，不会报错

### 6.5 导入流程（只有一条路，照着走就行）

1. 点 **① 下载模板** → 在「设备台账」页填好数据（从第 3 行开始）
2. 点 **② 上传填好的文件** → 系统**先算一遍**，弹出「确认导入」窗口，上面四个数字说得很清楚：

| 数字 | 含义 |
| --- | --- |
| **台新增** | 库里没有的设备，会新建这么多条 |
| **台更新** | 按 SN（或资产编号）匹配到已有设备，会更新它们的资料 |
| **行跳过** | 没被处理的（备注里标了「示例」的行、或关了「同 SN 更新」时的重复行） |
| **行失败** | 有问题的行，窗口里会直接列出「第几行：什么原因」 |

3. 看清楚了点 **✅ 确认导入 N 台** → 完成后提示：

```
导完了：新增 12、更新 3、跳过 1
```

> ✅ **这一步是安全的**：在你点「确认导入」之前，系统**什么都没写进数据库**。
> 想放弃就直接关掉窗口。

**两个选项**（在导入卡片里展开「导入选项」）

- ☑ **表格里的组织 / 分类不存在时，自动新建**：建议勾选，省得先去建组织
- ☑ **同一个 SN 已存在时，更新那台设备**：建议勾选；取消则同 SN 的行会被跳过

### 6.6 导入失败常见原因

| 报错 | 原因与解决 |
| --- | --- |
| 表头无法识别 | 用了自己的表格但表头完全不认识。请用系统模板，或确保至少有「设备分类」「SN 序列号」这类标准列名 |
| 状态「X」无法识别 | 状态列的值不在下拉选项里，改为标准的七个状态之一 |
| 资产编号「X」已存在 | 同编号设备已存在，把这一行的编号留空（自动生成）或改成别的 |
| 分类「X」不存在 | 没勾「自动创建缺失的组织/分类」时会出现，勾上即可 |
| 表格里没有数据行 | 数据没填在「设备台账」页，或填到了「填写示例」页 |
| 表格里没有数据行 | 数据没填在「设备台账」页，或填到了「填写示例」页 |
| 第 N 行：SN「X」已存在 | 该 SN 在库中已有记录；勾了「更新」会更新，没勾会跳过 |

## 七、自动盘点：GLPI Agent 自动上报

> 前面第五章的拍照识别是**人工一台台录**。这一章是**让电脑自己报**——
> 在每台 Windows 电脑上装一个 GLPI Agent，它会把主机名、序列号、品牌、型号、
> CPU、内存、硬盘、操作系统、网卡 MAC / IP、登录用户，**以及接在这台机器上的显示器的序列号和尺寸**
> 自动报给本系统。之后不再需要举着手机拍铭牌。

### 7.1 它是怎么工作的（一张图看懂）

```
每台电脑上的 GLPI Agent  ──①打招呼(CONTACT)──▶  本系统 /api/agent
                         ◀─②回话：用 glpi 协议、6 小时后再来─
                         ──③交盘点(INVENTORY，gzip 压缩)──▶  解析 → 落库
                                                              │
                                              出现在「自动盘点 → 待认领机器」
                                                              │
                                              你点「认领」→ 成为正式台账资产
                                                              │
                                              以后每次上报自动刷新 MAC/IP/系统/CPU/内存/硬盘
```

**⚠️ 最重要的一条设计**：agent 报上来的是**机器自己的序列号**（如 `640HP72`），
它**不知道**企业的资产编号（`PC-2026-0017`）。所以系统**绝不会自动往台账里插数据**——
一律先落在「待认领」里，等你确认。这是防止台账被搞脏的关键。

### 7.2 三步装好

#### 第一步：生成上报令牌

管理端 → 左侧 **自动盘点** → **上报令牌** 页签 → **生成令牌**。

- 建议按批次/区域分开建（「办公区电脑」「财务部」），以后要停用某一批就停那一个
- **令牌只在生成时显示一次**（库里只存哈希），关掉窗口就看不到了
- agent 那边把令牌同时填进「用户名」和「密码」两个位置

#### 第二步：在每台电脑上跑一条命令

把项目里的 `scripts\install-glpi-agent.ps1` 拷到目标电脑（或用共享目录），
**用管理员身份的 PowerShell** 执行：

**局域网内的电脑（绝大多数，推荐）**

```powershell
powershell -ExecutionPolicy Bypass -File install-glpi-agent.ps1 `
  -Server "http://192.168.1.100:8080/api/agent" -Token "你的令牌"
```

**要带回家的笔记本（走公网穿透）**

```powershell
powershell -ExecutionPolicy Bypass -File install-glpi-agent.ps1 `
  -Server "https://itam.example.com:12345/api/agent" -Token "你的令牌" -UsePublic
```

加了 `-UsePublic` 后，脚本会**自动从服务器把 CA 证书拉下来**配好（`/api/agent/ca`），
所以 **TLS 校验照常开着**，不需要用 `no-ssl-check` 那种关掉校验的将就办法。

**这台电脑没有外网**（先把 MSI 拷过去）

```powershell
powershell -ExecutionPolicy Bypass -File install-glpi-agent.ps1 `
  -Server "http://192.168.1.100:8080/api/agent" -Token "你的令牌" `
  -MsiPath "D:\GLPI-Agent-1.19-x64.msi"
```

脚本会：下载官方 MSI（22MB）→ 静默安装成 Windows 服务 → 写入服务器地址与令牌 →
重启服务 → **立刻做一次盘点**（不用等定时任务）。全程约 1~2 分钟。

装完屏幕上会打印下一步去哪儿看：**自动盘点 → 待认领机器**。

#### 第三步：认领

回到管理端 **自动盘点 → 待认领机器**：

| 情况 | 系统怎么做 |
| --- | --- |
| 台账里已有这台机器（SN 对得上） | 排在推荐第一位，点一下就能认领。**只补空字段**，你人工填过的使用人、位置、备注、采购信息一律不动 |
| 台账里没有 | 点「认领」→「新建设备并认领」，分类按机箱类型自动选（Laptop→笔记本、Desktop→台式主机、Server→服务器） |
| 有人误报 / 是台临时机器 | 点「忽略」，删掉这条上报副本；它之后再上报会重新出现 |

认领成功后：设备的「流转记录」里会留下凭据，`extra` 里记下机器身份（deviceid / UUID），
以后同一台机器再上报就认得出是它。

### 7.3 显示器：不用再拍背面标签了

这是**最省事的一项**。agent 会通过 EDID 读出接在主机上的显示器：

| 拿到什么 | 说明 |
| --- | --- |
| **序列号** | 真正的显示器 SN（如 `ABH55D`） |
| 型号代号 | 如 `DJCP6`（厂商内部型号串） |
| 厂商 | 如 `Sharp Corporation` |
| **尺寸 / 生产年份** | 从 EDID 的 `description` 解出来（如 `32/2015` → 32 英寸、2015 年） |

到 **自动盘点 → 显示器** 页签：

- **认领到已有显示器资产**：会按序列号优先匹配；没有 SN 的显示器资产会按型号/尺寸给出「待确认」候选
- **新建一台显示器资产**：序列号、品牌、型号、尺寸（如「32 英寸」）自动填好，备注里写明「由自动盘点识别（接在 X 上）」

> ⚠️ 实话实说：EDID 读取依赖显卡驱动走 DDC/CI 通道，**个别显示器读不出序列号**（厂商没写，或者走的是老式 VGA 接口）。
> 那种情况这一行会显示「EDID 未提供」，仍然需要人工补一次——但至少比每台都拍省事。

### 7.4 自动同步：认领之后会发生什么

认领过的机器，之后每次上报都会自动更新这几个字段（**都是"机器事实"**）：

| 字段 | 说明 |
| --- | --- |
| MAC 地址 / IP 地址 | 机器换网口、换网段会自动跟上 |
| 操作系统 | 重装系统后自动更新 |
| CPU / 内存 / 硬盘 | 加内存、换硬盘后自动更新 |

**永远不动的字段**（这些是"人的决定"）：资产编号、设备分类、所属组织、使用人、
状态、采购信息、照片、备注。

> 想临时停掉某台机器的自动同步？在待认领列表里点它那行的「同步」旁边的开关即可
> （接口是 `POST /api/agent/machines/<id>/sync`，`auto_sync` 传 `false`）。

### 7.5 关于「部分盘点」——这一条关系到数据安全

GLPI Agent 默认**大部分时候只上报变化的那几个部分**（协议里叫 partial，默认 14 次里只有 1 次是全量）。
所以本系统的入库逻辑是**按段合并**：

| 这次报了什么 | 怎么处理 |
| --- | --- |
| 全量盘点 | 整份替换（机器换了配置，某一段没了就该没了） |
| 部分盘点（`partial: true`） | **只覆盖这次报上来的段，没报的段原样保留** |

> 举个例子：某次只报了 CPU 段，那么软件列表、显示器、内存、硬盘的信息**都还在**。
> 要是写成"整条覆盖"，第二次上报就能把这些数据洗掉一半——这是这个功能里最容易写错的地方，
> 所以测试里专门钉了这条（`tests/agent.js` 里的「部分盘点：没报的段必须原样保留」）。

### 7.6 隧道 / 内网穿透环境下要注意什么

| 机器在哪 | 用哪个地址 | 为什么 |
| --- | --- | --- |
| **公司局域网内** | `http://192.168.1.100:8080/api/agent` | 直连，不碰证书、不占穿透流量 |
| **要带回家的笔记本** | `https://itam.example.com:12345/api/agent` | 在家里也连得上；脚本会自动配好 CA 证书 |

几条容易踩的：

- **agent 是"机器 → 服务器"推数据，和你在外面打开网页是两条路**。内网机器不需要走穿透，
  走穿透等于绕远路（数据先发到樱花服务器再绕回来），白占流量还更慢。
- **agent 的 `server` 只能填一个地址**。填两个会导致同一份盘点执行两次、重复上报。
- **穿透断了不会丢数据**：协议规定上报失败时 agent 要保留盘点结果、按服务端给的
  `expiration` 到期重试。内网那批更是完全不受影响。
- 流量不用担心：一次完整盘点的 JSON 是几十 KB 量级（软件列表特别多的机器才大），压缩后更小。

### 7.7 出问题怎么查

| 现象 | 去哪里看 |
| --- | --- |
| 「待认领」里一直没东西 | 管理端 **自动盘点 → 上报历史**，看有没有记录。一条都没有 = 网络或地址不对 |
| 上报历史里一堆「鉴权」失败 | 令牌不对或被停用了。重新生成一个，用脚本重装（或改注册表） |
| 上报历史里显示「解析」失败 | 报文格式不对，把 agent 日志发我 |
| 想直接看 agent 在干什么 | agent 电脑上：`C:\Program Files\GLPI-Agent\logs\glpi-agent.log`，或运行 `& "C:\Program Files\GLPI-Agent\glpi-agent.bat" --force --debug` |
| 想手工验证通道通不通 | 浏览器打开 `http://192.168.1.100:8080/api/health`，能出 JSON 就说明网络没问题 |
| 手边没有 agent 也想测 | agent 电脑上跑 `glpi-agent --local - --json`，会把盘点直接打到屏幕上 |

**服务器侧的关键信息**（安装指引页签里也有一份）：

| 项目 | 值 |
| --- | --- |
| 上报入口 | `http://192.168.1.100:8080/api/agent`（也认 `/front/inventory.php`，照抄 GLPI 官方文档配的人不会踩坑） |
| 认证方式 | HTTP Basic，用户名和密码都填令牌 |
| 单次上限 | 16 MB（未压缩） |
| 支持的压缩 | gzip / zlib(deflate) / brotli / 不压缩 |
| CA 证书 | `http://192.168.1.100:8080/api/agent/ca`（公开，可匿名下载） |

### 7.8 只支持"电脑盘点"

本系统只处理 `inventory` 这个动作（也就是电脑/服务器盘点）。agent 的
`netdiscovery`（网络扫描发现）、`netinventory`（网络设备盘点）、`deploy`、`collect`
这几种任务的报文结构完全不同，硬塞进来只会造出一堆空字段的垃圾记录，
所以服务端会**明确回绝并说明**（回 2xx，避免 agent 反复重试）。

需要网络设备自动发现的话，那是另一件事，得单独做 SNMP 采集。

## 八、组织架构与设备分类

### 8.1 组织架构（🏢）

支持**无限层级**：集团 → 公司 → 部门 → 小组。

- 左侧是**树形图**，点组织名前的箭头可展开/收起
- 右侧是**表格**，显示每个组织的类型、编码、负责人、设备数
- 点「＋ 新增组织」新建；编辑时可以改「上级组织」来调整层级
- **设备数统计**：父组织会统计所有下级的设备

**注意**：删除组织前必须先处理它下面的子组织和设备（或勾选强制转移）。

### 8.2 设备分类（🗂️）

- 每个分类有：名称、编码、**资产编号前缀**、图标、主题色、**专属字段**
- **资产编号前缀**决定自动生成的编号，如「显示器」前缀 `MON` → `MON-2026-0001`
- **专属字段**：给该分类特有的属性，**电脑端和手机端录入时都会自动出现**
- 已有设备的分类不能直接删除，需要先处理设备

**专属字段支持 4 种类型**

| 类型 | 说明 |
| --- | --- |
| 文本 | 自由输入 |
| 数字 | 只能填数字 |
| 日期 | 日期选择器 |
| **下拉选项** | 只能从预设选项里选，避免各人写法不一致 |

**「使用人 / 存放位置」也是专属字段（2026-09 起）**

它们以前是手机端写死的两个输入框，现在归分类管了 —— 出厂默认每个分类都带这两项，
你可以按分类自由处理：

| 想做什么 | 怎么做 |
| --- | --- |
| 换个叫法（如「使用人」→「领用人」） | 改那一行的**显示名**。只影响界面文字，**已经存的数据不受影响** |
| 改成下拉（如只允许几个固定房间） | 类型选「下拉选项」，填选项 |
| 某个分类不要这一项 | 把那一行**删掉**，保存。之后该分类的录入界面就不再出现它 |
| 换个位置（想排在 CPU 后面） | 上下调整行的顺序即可（界面按这个顺序渲染） |

> ⚠️ 改 key（英文标识）等于换了一个字段：`owner_name` / `location` 这两个 key 是写进设备正式字段的，
> 改成别的 key 会存到「扩展字段」里，不要随手改。下面这张表列了**会写进正式字段**的 key。

**哪些 key 会写进设备的正式字段**

| key | 对应字段 |
| --- | --- |
| `owner_name` | 使用人 |
| `location` | 存放位置 |
| `cpu` / `memory` / `disk` / `os_name` | CPU / 内存 / 硬盘 / 操作系统 |
| `ip_address` / `mac_address` | IP 地址 / MAC 地址 |
| `screen_size` | 屏幕尺寸 |
| `owner_employee_no` / `owner_phone` | 使用人工号 / 电话 |
| `supplier` / `remark` | 供应商 / 备注 |
| 其它任意 key | 存进扩展字段（导出 Excel 时同样成列） |

> 编辑框里点一下 key 输入框，会下拉提示上面这些常用 key，不用背。

**怎么加一个下拉选项**（以「显示器 → 屏幕尺寸」为例）

1. 进入 **🗂️ 设备分类**，找到「显示器」，点「编辑」
2. 在「专属字段」里找到 `screen_size` 那一行
3. 类型选 **下拉选项**，右边会出现「选项」输入框
4. 填入 `24寸, 27寸`（**逗号分隔**）
5. 保存

设置好后：

- 电脑端新增/编辑显示器时，「屏幕尺寸」变成下拉框
- 📱 **手机端拍照录入选到「显示器」分类时，也会出现这个下拉框**
- 想增减尺寸，改这里的选项即可，不用改代码

> 系统已预置：显示器 = `24寸 / 27寸`；笔记本电脑 = `13.3寸 / 14寸 / 15.6寸 / 16寸`。
> 如果某台设备的历史值不在选项里，下拉框会把它临时保留下来，不会因为改配置而丢数据。

## 九、系统设置

左侧 **⚙️ 系统设置**（需要「查看/修改系统设置」权限）。

| 项目 | 说明 |
| --- | --- |

### 9.1.1 手机录入默认值

系统设置里的 **📸 手机录入默认值** 卡片 —— 配手机端「拍照识别入库」表单里那几个下拉的默认选中项：

| 项目 | 说明 |
| --- | --- |

配好之后手机端一打开就是这个选项（仍然可以随时改）。详见[第五章的「预设默认值」](#五手机端拍照识别入库)。

> ⚠️ 如果后来把那个分类/组织删掉了，系统会自动忽略这个默认值（不会让手机端选到不存在的项）。
> 换过供应商名字的话，回这里重新选一次即可。

### 9.1.2 照片归档

系统设置里的 **📸 照片归档** 卡片（默认全开，一般不用动）：

| 项目 | 默认 | 说明 |
| --- | --- | --- |
| 保存原图 | ✅ 开 | 手机拍到多清楚就存多清楚（最高 4K），设备详情可放大看铭牌小字 |
| 保存缩略图 | ✅ 开 | 导出 Excel 时嵌进单元格用的就是它 |

### 9.2 识别服务（手机拍照识别用）

| 项目 | 说明 |
| --- | --- |
| 服务提供商 | 视觉大模型 / 百度 OCR / 腾讯云 OCR / 阿里云 / 自定义 / 本地模拟 |
| 服务商预设 | 选一家自动填好地址与模型（推荐智谱 GLM-4.6V-Flash，免费） |
| API Key | 服务商的密钥，保存后只显示为 `abcd****wxyz` 掩码 |
| 图片编码方式 | 一般选「自动」 |
| 置信度阈值 | 低于该值的识别结果会在手机端标红提示人工确认 |
| 🧪 测试识别 | 点一下验证密钥是否可用 |

### 9.4 安全机制（不需要配置，知道有这回事就行）

系统默认就带这些防线，**不用开开关**。列在这里是为了：出问题时你知道是它在起作用，而不是当故障排查。

| 机制 | 作用 | 你会看到什么 |
| --- | --- | --- |
| 登录失败限流 | 防口令爆破（账号级 / 来源 IP 级 / **全站级**三道，见第十章） | 提示「登录失败次数过多」 |
| 接口限流 | 防自动化狂刷；扫码、识别、Excel 导入导出另有更严的额度（每分钟 240 次） | 提示「请求过于频繁」，等 1 分钟 |
| 重活并发限制 | 服务端扫码解码/图像识别很吃 CPU，同时只跑 4 / 6 个，多的**直接丢弃**而不是排队 —— 排队会让整个系统（含所有页面）一起变慢 | 偶发「服务繁忙，请稍后重试」，再按一次快门即可 |
| 浏览器安全策略（CSP 等） | 防页面被注入后加载外部脚本、把数据外发到别的网址 | 正常使用无感；若你把某个外部图片/脚本贴进备注里，它不会被加载（这是故意的） |
| 照片访问控制 | 照片必须登录才能看，且只允许浏览器自己缓存 | 换台没登录的电脑打不开照片链接 |
| 上传缓存 | 导出表格里的照片链接带临时令牌，令牌重置后旧链接失效 | 「Excel 表格」页可一键重置令牌 |

管理员可调的部分（改环境变量后重启服务）见 `README.md` 的「安全加固」一节。

## 十、常见问题

### 登录相关

| 问题 | 解决 |
| --- | --- |
| 登录页打不开 | 确认服务在运行（管理员跑 `scripts\status.cmd`），确认地址端口正确 |
| 提示「用户名或密码错误」 | 检查大小写；连续错 5 次会锁 10 分钟 |
| 提示「账号已被锁定」 | 等 10 分钟，或让管理员在「用户管理」里点「解锁」 |
| 提示「正在等待管理员审核」 | 你的自助注册还没被通过 |
| 提示「账号已被停用」 | 联系管理员 |
| 提示「该 IP 登录失败次数过多」 | 同一台电脑 15 分钟内错太多次了，等一会儿再试（**换设备也绕不过**，见下面的「登录为什么会失败」） |
| 登录后看不到某些菜单 | 正常——你的角色没有该权限 |

#### 登录为什么会失败：系统在防爆破

登录失败有两个方向的限制，同时生效：

| 限制 | 阈值 | 什么时候会遇到 |
| --- | --- | --- |
| 单个账号 | 连错 5 次 → 锁 10 分钟 | 自己记错密码，或有人在猜你的密码 |
| 单个来源 IP | 15 分钟内错 10 次 → 该 IP 暂停 | 一台电脑上多人反复试 |
| **全站** | 5 分钟内累计错 200 次 → 全体暂停几分钟 | 有人在批量撞库 |

最后一条是**故意不看来源地址**的：攻击者可以伪造来源地址，但伪造不了「失败总次数」。所以宁可短暂影响所有人，也不让口令被慢慢试出来。日常使用（几个人手误输错）远远到不了这个量。

管理员如果确认是误伤，等几分钟即可；不需要重启服务。

### 使用相关

| 问题 | 解决 |
| --- | --- |
| 页面显示旧内容 | `Ctrl + F5` 强制刷新 |
| 提示「请求过于频繁」 | 短时间内发出的请求太多被限流了，等 1 分钟再操作（批量导入/连续扫码时偶尔会遇到） |
| 扫码时偶发「服务繁忙，请稍后重试」 | 同一时刻扫码/识别的人太多，服务端主动丢弃了多余的请求（**不是故障**，也不会卡住其他人的页面）。稍等一两秒再按一次快门即可 |
| 顶部搜索没反应 | 输入关键词后要按**回车** |
| 找不到刚录入的设备 | 检查筛选条件是否被限制；点「重置」；确认保存成功（有绿色提示） |
| 误删了设备 | 去 **🗑️ 回收站** 点「恢复」 |
| 保修预警里出现很多设备 | 说明这些设备快到保修期了，及时联系供应商续保或更新 |

| 项目 | 值 |

| 状态 | 含义 | 建议用法 |
| --- | --- | --- |
| **在用** | 已分配给员工使用 | 填了使用人就是这种状态 |
| **库存** | 未分配、可领用 | 新采购入库 |
| **闲置** | 暂时没人用但还在 | |

| **丢失** | 遗失 | |

### 关键字段

| 字段 | 为什么重要 |
| --- | --- |
| **资产编号** | 公司内部唯一标识，用于贴标签、盘点 |
| **SN 序列号** | 厂商唯一标识，**唯一**。查重、对接厂商保修都靠它 |
| **所属组织** | 决定设备归属，统计和筛选都靠它 |
| **使用人 + 工号** | 责任到人，离职交接时用「批量交接」 |

### 效率小技巧

1. **电脑上大批量** → 用 Excel 导入；**手上是照片** → 用批量识别（电脑端「设备台账 → 批量识别录入」或手机端「批量识别入库」）；**现场零星录入** → 用手机拍照
2. 手机识别后**务必扫一眼 SN**，识别置信度再高也要人工确认
3. 盘点时用手机**扫码核对**，会自动记录核对结果
4. 打印资产二维码贴在设备上（设备详情页可打开二维码），以后手机一扫就能查
5. 顶部全局搜索框支持 SN，客户报故障时直接粘 SN 回车定位
6. 定期看仪表盘的「保修即将到期」，比翻 Excel 靠谱
7. 批量识别的照片**先拍清楚再传**（铭牌填满画面、光线足、别反光），比事后一张张补数值
